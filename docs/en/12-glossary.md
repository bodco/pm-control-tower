# 12. Glossary

| Term | Meaning |
|---|---|
| **Control Tower (CT)** | 1) The operations centre page in Notion with 11 databases; 2) the name of the whole framework |
| **Cowork mode** | The Claude Desktop mode with access to files, bash, the browser, MCP and scheduled tasks. The centre of the framework |
| **MCP connector** | Model Context Protocol: a way to give Claude the tools of an external system (Slack, Notion, Jira...) |
| **Skill** | A folder with a `SKILL.md` (frontmatter + instructions) that Claude applies based on the triggers in its description |
| **Engine skill** | A skill without a project prefix; reads the config registry and works with any project |
| **Project skill** | A skill with a `<slug>-` prefix, tied to a single project |
| **Tombstone** | A skill left behind after a rename, with a description of "DEPRECATED... RENAMED to..."; does nothing |
| **Frozen skill (HISTORICAL)** | A skill for a component that went to the client; fires only on an explicit request |
| **The `projects/` registry** | Skill infrastructure with one config file per project plus the rules (Rule Zero, Default Project Rule, Naming) |
| **Rule Zero** | The config beats any skill or document |
| **Default Project Rule** | If the project is not named explicitly, ask, do not guess |
| **Step 0** | The first step of every engine: identify the project, read the config |
| **Report Storage** | A skill section: where to save the result and with which properties (Reports DB) |
| **Access Matrix** | A config section: access to each resource with dates |
| **Engagement Status** | A config section: model, team, scope, QA, dates |
| **Metric Continuity** | A warning in the config that metrics are not comparable across a team or scope change date |
| **Former Members** | A table of people who left the project, with the date; they are never deleted |
| **Transcript Alias Map** | How transcripts mangle names → the real people |
| **Cultural Profile** | Culture positions per Erin Meyer (Culture Map) and individual calibration of the client's people |
| **Downgrader multiplier** | A severity coefficient for the client's indirect phrasing |
| **Threads** | The database of inbound communications (Slack, Email, Other) with statuses |
| **Awaiting Reply / Need Follow-up / Spectator Mode / Replied / Closed / Claude** | Thread statuses |
| **Red dot (🔴)** | The icon of a thread whose last author is not from our team |
| **Topics** | The database of cross-cutting themes across meetings and threads |
| **Decisions DB / Decision Log** | The log of decisions; the source of constraints for briefs |
| **Reports DB** | The archive of all generated reports, with Type, Skill, Visibility |
| **Risks DB** | A living risk register with Visibility (Internal/External/Both) |
| **Tasks Tracker (Personal Operating System)** | The database of all the PM's tasks across projects and outside them; personal capacity management; it does not duplicate or sync Jira, the link is only through the optional `Jira Issue Key` |
| **The Source field** | Who created the task in the Tasks Tracker: manual, inbox or the name of a skill |
| **Core (Core PM Framework)** | ~80% of the system, universal: Notion CT, Tasks Tracker, the mail pipeline, the rhythm, the config registry, the engines |
| **Project Adapter / Edge Plugin** | ~20% of the system, tailored to a specific client: `<slug>-*` skills, export parsers, browser collection, KBs. The norm, not debt |
| **Zero-API Access** | The situation where the client does not issue API tokens for their tracker or chat; in the config, `task_tracker.api_access: false` |
| **Graceful degradation** | An engine's behaviour when a source is missing: do not fail, switch to `fallback_source`, and mark it in the report |
| **`task_tracker`** | A config section: `type` (jira_server, jira_cloud, linear, trello, client_notion, manual), `api_access`, `fallback_source` (manual_export, meeting_action_items, email_summaries) |
| **Current State** | A distilled page of the project's state, updated incrementally every day |
| **Scheduled task** | A prompt with a cron schedule in Cowork (Mac) |
| **Routine** | A cloud scheduled task (Claude Code Remote), without the Mac |
| **Autopilot** | The set of scheduled tasks and routines |
| **Prep** | A preparation document for a meeting, generated by a skill |
| **Skill Health Check** | A monthly cloud audit of skills against the configs |
| **Monthly Memory Digest** | A monthly cloud digest of each project's state, appending decisions to Decisions |
| **Knowledge Base (KB) for code** | `SYSTEM.md`, `SDLC.md`, component KBs, `LESSONS.md` for code review and RCA |
| **RCA** | Root cause analysis; on Acme it is `acme-debug` |
| **Frozen snapshot** | A local clone and KB of a component we have lost access to; read-only history as of a date |
| **Bridge** | The link between a cloud Claude session and the Mac (files, local MCP) |
| **`.ai/`** | The folder of the two-agent protocol at the root of the project |
| **CONTRACT.md** | The `.ai/` protocol; only a human writes it |
| **Single-Writer** | One writer per file; a correction = a new file |
| **Brief** | `.ai/tasks/<task_id>.md`, written by Gemini |
| **Report** | `.ai/reports/<task_id>.md`, written by Claude |
| **QA note** | `.ai/reports/<task_id>.qa-N.md`, written by Gemini |
| **`current.md`** | A pointer to the active task, written only by Gemini |
| **`challenged_constraints`** | The report section where Claude challenges outdated agreements with evidence |
| **`task_id`** | `<JIRA-KEY>-<slug>` or `NOJIRA-<YYYYMMDD>-<slug>` |
| **Spark** | The Gemini Desktop mode in which the Gemini skills run |
| **`notion-project-brief`, `project-decision-qa`** | Gemini skills: a brief from history, QA against decisions |
| **PM Toolkit** | A section of the Notion Knowledge Base: metrics, report and document templates, the meeting map, senior practices. It has a machine-readable version, `_standards.md` |
| **`_standards.md`** | A file in the `projects` skill: standards that are the same for all projects (metrics, profiles, agendas, the reader rule, the minimum set of documents, RAID, decisions). It yields to the project config and beats the Toolkit in Notion (`14`) |
| **PM Profile** | A section of the project config: case, phase, approach, metric profile, contract and hours cap, SLA, milestones, decision rights |
| **The reader rule** | Every report and prep meant for a human carries a 🟢🟡🔴 status, outcomes, risks with actions, and a "Decisions needed" section, even an empty one |
| **Kind (Risks DB)** | The RAID record type: Risk, Assumption, Issue, Dependency; empty = Risk |
| **Door (Decisions DB)** | A One-way (expensive to reverse) or Two-way (cheap) decision |
| **`project-lifecycle`** | The engine for a project's rare moments: kickoff, handover-in, health-check, team-onboarding / offboarding, closure (`14`) |
| **Project Health Check** | A monthly audit of the project's state across 8 areas with evidence (the 2nd of the month, in the cloud). Not to be confused with the Skill Health Check, which audits skills against the configs |
| **`change-request`** | The scope change engine: buckets A / B / C, the Extras Log, a CR draft, the decision in Decisions |
| **Buckets A / B / C** | A: trivial, logging only; B: real hours; C: touches data, money, security or public contracts, always a CR regardless of size |
| **Extras Log** | A page under the project page listing every client request, including the free ones; the basis for the goodwill budget and for transparency in the monthly report |
| **Goodwill budget** | The share of the hours cap spent on free trivia (`goodwill_budget_pct`, default 10%, to be calibrated); exceeding it is a scope creep signal |
| **Locked template** | A reference report whose structure beats the `client-report` formats; new blocks are only proposed to the PM |
| **[EXT-QA]** | The historical prefix for tickets covering QA of client PRs (Acme, until 2026-07-31) |
| **Tempo** | Time tracking in Jira; exports for client reports and estimates |
| **PROJ** | The Jira project key for Acme |
