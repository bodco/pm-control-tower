# 17. Live tips: асистент на дзвінку

[English](../en/17-live-tips.md) · [До змісту](README.md)

Live tips - це блок, який слухає дзвінок разом з ПМом і підказує в чаті Cowork. Аудіо
розпізнається локально на Маку, назовні нічого не йде. Скіл читає транскрипт рядок за рядком
і звіряє його з контекстом проєкту. На старті показує твій спіч чи статус, далі підказує, коли це допомагає: прохання, схоже на
нову вимогу, обіцянка дати чи оцінки, суперечність ухваленому рішенню, неточна або неповна
відповідь, перехід співрозмовників на іншу мову, момент, де можна додати факт чи поставити
питання. Миттєві картки з підготовки з'являються за 1-2 с після фрази-тригера, а кнопка
🆘 HELP NOW дає наступне речення, коли ти застряг посеред відповіді. Необов'язкові локальні
доповнення розрізняють голоси співрозмовників (імена даєш ти, нічого не вгадується) і
шукають факти за змістом, а не лише за ключовими словами. Покриває і презентації, і
інтерв'ю (спостерігач, інтерв'юер, коуч). Live tips у **беті**, і здебільшого це обв'язка навколо
чужих відкритих моделей: див. [розділ 13](#13-що-тут-відкритий-код-а-що-зроблено-тут). Після дзвінка підсумок іде в Meetings DB:
в уже наявну сторінку мітингу (наприклад, створену Notion AI Meeting Notes) або в нову, якщо
такої немає.

Є також **застосунок Live Tips (бета)**: нативний застосунок macOS у рядку меню, що крутить той
самий цикл без чату Cowork, з твоїм власним API-ключем Claude. Він читає ті самі правила і
показує те саме вікно-суфлер. Див. [розділ 14](#14-застосунок-live-tips-бета).

Документ розрахований на три ситуації:

1. відтворити все з нуля на новому Маку;
2. пригадати, як воно працює, коли щось зламалось;
3. колега хоче поставити те саме в себе.

## 1. Як це влаштовано

```
                    Мак (локально)                                    Cowork (хмара)
┌──────────────────────────────────────────────────────────┐    ┌──────────────────────────┐
│ LaunchAgent  ──стежить за──>  control/                   │    │ скіл live-tips           │
│     │ з'явився start.json                                │<───│  пише control/start.json │
│     v                                                    │    │                          │
│ Terminal: bin/run.command                                │    │  long-poll:              │
│     v                                                    │    │  bin/read_delta.py       │
│ src/transcriber.py                                       │    │  -> нові рядки           │
│   ├─ bin/audiocap --source mic     (мікрофон)            │    │  -> тригери -> підказка  │
│   ├─ bin/audiocap --source system  (системний звук)      │    │     в чаті               │
│   ├─ VAD ріже на фрази                                   │    │                          │
│   ├─ Whisper large-v3-turbo (MLX) на кожну фразу         │    │  "стоп" -> control/stop  │
│   ├─ прибирає відлуння і галюцинації                     │    │                          │
│   └─> <проєкт>/live/2026-10-10-2348-<назва>.md ──────────┼───>│  підсумок + сторінка     │
│       state/status.json  (стан для скіла) ───────────────┼───>│  в Notion Meetings DB    │
└──────────────────────────────────────────────────────────┘    └──────────────────────────┘
```

Чому саме так:

- **Локальний Whisper.** Розмови з клієнтом не йдуть у сторонній сервіс транскрипції. Модель
  `mlx-community/whisper-large-v3-turbo` працює на Apple Silicon через MLX. Мережа потрібна
  лише раз, щоб скачати модель (~1.6 ГБ).
- **Два канали замість одного.** `audiocap` (Swift) окремо пише мікрофон і системний звук.
  Системний звук знімається через Core Audio process tap (macOS 14.2+), тому BlackHole не
  потрібен, а зміна навушників чи динаміків не ламає запис. Завдяки двом каналам
  транскрипт знає, хто говорить: `Я` = мікрофон, `Співрозмовник` = усі інші.
- **Фіксована мова мікрофона.** Мова ПМа на дзвінку відома наперед (`me_lang`), а для
  співрозмовників Whisper вибирає мову лише з дозволеного набору (`langs`, напр. `en+es`).
  Це помітно краще за повний автодетект: українська не перетворюється на російську,
  іспанські репліки не перекладаються англійською.
- **Terminal, а не фоновий процес.** macOS видає дозволи на мікрофон і запис системного звуку
  застосунку. Запис стартує у вікні Terminal, тож дозволи належать Terminal і даються один раз.
  LaunchAgent лише відкриває це вікно, коли скіл кладе `control/start.json`.
- **Файл як інтерфейс.** Скіл працює з Маком через shell у підключеній папці Cowork
  (`device_bash`) і нічого не знає про аудіо. Між скілом і записом стоять лише файли:
  `control/start.json`, `control/stop`, `state/status.json` і сам транскрипт. Від 1.8.0
  механічні кроки (старт, стоп, стан запису, перевірка підготовки, стан скіла, цифри для
  підсумку) скіл робить одним помічником `bin/lt`, а не відтворює їх з опису.
- **Швидке працює без моделі.** Цикл моделі відстає від розмови на 10-20 с. Тому все, що має
  бути миттєвим, працює в самому записувачі: миттєві картки, пошук у книзі фактів, позначка
  ❓ на питанні, локальна частина 🆘 HELP NOW і трекер презентації. Головна робота скіла до
  дзвінка: підготувати ці файли.
- **Необов'язкові локальні шари.** Розпізнавання спікерів (sherpa-onnx) і смисловий шар
  (Ollama з `bge-m3`) теж працюють на Маку. Обидва вимкнені, доки їх не встановиш, і жоден не
  затримує ні рядок транскрипту, ні підказку.

## 2. Компоненти

Код лежить у [`tools/live-transcriber/`](../../tools/live-transcriber/), скіл у
[`plugin/skills/live-tips/`](../../plugin/skills/live-tips/).

| Файл | Роль |
|---|---|
| `install.sh` | Одноразове встановлення: збірка `audiocap`, venv з `mlx-whisper`, модель, LaunchAgent, тест дозволів. Можна запускати повторно |
| `config.json` | Модель, мітки каналів, мови за замовчуванням, `launchd_label`. Поля зі `start.json` мають пріоритет |
| `src/audiocap.swift` | Захоплення аудіо: `--source mic` або `--source system`, на виході float32 16 кГц mono у stdout. Сам перепідключається при зміні пристрою |
| `src/Info.plist` | Вшивається в бінарник, містить тексти запитів дозволів |
| `src/transcriber.py` | Серце: два потоки захоплення, VAD (webrtcvad, без нього енергетичний), Whisper, фільтр галюцинацій, прибирання відлуння, запис рядків, `status.json` |
| `bin/run.command` | Запускає `transcriber.py --from-control` у вікні Terminal "Live transcriber" |
| `bin/on-control.sh` | Викликається LaunchAgent при зміні `control/`. Якщо є `start.json` і запис не йде, відкриває Terminal |
| `bin/read_delta.py` | Один виклик на ітерацію скіла: дописує нові підказки у вікно (`--emit-stdin`), зливає рядок скіла `{"kind":"state"}` у `<stem>.state.json`, чекає до `--wait` с на нові рядки транскрипту чи введення з вікна (на питанні не чекає: адаптивна пауза), віддає лише нове плюс рядки `@@` (таблиця в "Як побудований скіл"). `auto` замість зсуву бере його з файлу стану |
| `bin/lt` | Помічник скіла: `start`, `status`, `stop`, `prep-check [--adopt-prep] [--fix]`, `state`, `wrapup-data`, `speakers`, `index`, `search`. Перекладає шляхи між Маком і папкою Cowork через `--mac-root <work_root>` (або `LT_MAC_ROOT`) і прямо каже, що не вдалося. `bin/lt` без аргументів показує використання |
| `bin/install-voices.sh` | Необов'язково: ставить розпізнавання спікерів (`sherpa-onnx` у `.venv`, модель WeSpeaker у `models/`, самоперевірка). Можна запускати повторно |
| `src/semantic.py` | Необов'язковий смисловий шар: вектори через локальну Ollama (`bge-m3`), індекс проєкту, пошук за змістом |
| `src/prompter.swift`, `src/prompter.html` | Вікно-суфлер (будова в розділі "Вікно-суфлер"); показує `*.tips.jsonl`, пише питання й налаштування в `*.inbox.jsonl`. Збирається в `bin/prompter` |
| `launchd/live-transcriber.plist.template` | Шаблон LaunchAgent (`WatchPaths` на `control/`) |
| `plugin/skills/live-tips/SKILL.md` | Ядро скіла: незмінні правила, порядок пріоритетів, чекліст старту, цикл опитування, таблиця рядків `@@`, стоп |
| `plugin/skills/live-tips/references/*.md` | Модулі, які ядро читає за потреби (перелік у "Як побудований скіл") |
| `plugin/skills/live-tips/settings.yaml` | Усе особисте: мітки, шляхи, мови, правила підказок, часова зона |

Runtime-папки (не в git): `.venv/`, `bin/audiocap`, `logs/`, `state/`, `control/`,
`models/` (модель голосів), `voices/` (твоя локальна бібліотека голосів: ніколи не клади її в
репозиторій).

### Як побудований скіл (1.8.0)

До 1.7.0 скіл був одним SKILL.md приблизно на 97 КБ, і на довгих дзвінках це було видно:
правила з середини файлу забувались. Від 1.8.0 це невелике ядро плюс модулі, які читаються
лише тоді, коли потрібні.

| Частина | Що в ній |
|---|---|
| `SKILL.md` (ядро) | Робота одним реченням, шість незмінних правил, порядок пріоритетів, чекліст старту (у кожного кроку "готово, коли"), чекліст на кожне опитування, таблиця рядків `@@`, стан запису і завислий мікрофон, тригери, дієта і формат підказок, стоп |
| `references/start.md` | Шляхи, проєкт, опис зустрічі (аудиторія, тип, режим), мови, швидкий старт, підказка для Whisper |
| `references/speech.md` | Твій спіч чи статус на старті, ведення стендапу, вступне слово |
| `references/sweep.md` | Збір контексту в субагенті: бриф, Insight Bank, миттєві картки, книга фактів |
| `references/window.md` | Протокол вікна: кнопки-питання, оцінки, налаштування і підтвердження, `find:`, фокус, перемикання мови, питання в чаті, оновлення контексту |
| `references/checks.md` | Перевірка відповідей і відрізки, де питаєш ти (клієнтські дзвінки і дзвінки з шефом) |
| `references/culture.md` | Культурна лінза для клієнтських дзвінків |
| `references/proactive.md` | Моменти для коментаря та ініціативні підказки (лише коли проактивні увімкнені) |
| `references/research.md` | Фонові дослідження під час дзвінка |
| `references/presentation.md`, `references/hiring.md` | Два окремі типи зустрічей |
| `references/wrapup.md` | Підсумок, сторінка в Meetings DB, уроки |
| `references/start-chat.md`, `references/fallback-notion.md` | Стартові питання в чаті; запасний шлях через Notion AI |

Правила, які не порушуються ніколи: під час дзвінка хід не завершується (кожне повідомлення
йде через `SendUserMessage`, наступна дія завжди наступне опитування); одна ітерація це один
виклик `device_bash` без блокувальної роботи після старту запису; факти або тиша (підказка
несе число, дату, ім'я, статус, джерело, конкретне питання чи наступний крок, ніколи не
загальну пораду); жодних зобов'язань за ПМа (оцінок, дат чи обсягу, які не в його владі);
нікому нічого не надсилається, крім підсумку дзвінка у внутрішню Meetings DB; нічого не
вигадувати, ніколи не вживати довге тире, без абревіатур у підказках.

**Пріоритет, від найвищого:** 🆘 HELP NOW > 🔴 (пряме питання до тебе, "твоя черга", нова
вимога, зобов'язання, серйозна помилка на клієнтському дзвінку) > відповіді на твої питання
і непідтверджені налаштування > факт до теми, яку обговорюють зараз > прострочений стан чи
підготовка > проактивні підказки (лише якщо увімкнені) > план (спіч, чекліст). Жива тема
завжди важливіша за план.

**Кожне опитування** це один механічний прохід: є щось термінове (`@@SOS`, `@@DUE`,
непідтверджений `@@SET`)? Тригер 🔴 чи набране питання? Факт з брифу, карток чи книги фактів,
що пасує до останніх ~60 с? Інакше тиша і наступне опитування.

Що `read_delta.py` друкує, крім нових рядків:

| Рядок | Що означає |
|---|---|
| `@@SOS [t]` | Натиснули 🆘 HELP NOW: найвищий пріоритет, наступне речення, яке сказати |
| `@@ASK [t] <текст>` | Ти написав у вікні (`find:`, `focus:`, кнопки-питання, "стоп") |
| `@@SET <ключ>=<значення>` | Налаштування з вікна (`tips_paused`, `audience`, `call_type`, `proactive`, оцінки, ...) |
| `@@CARD`, `@@LATE` | Миттєва картка вже показана; підказка прийшла, коли ти вже почав відповідати |
| `@@MODE presenting\|discussion` | Ти говориш більшу частину останніх 2+ хвилин чи ні |
| `@@SPEAKERS S2="Ім'я" S3=?` | Змінились імена спікерів або прийшла запізніла мітка голосу |
| `@@DUE prep\|state\|ack <ключ>\|wrapup` | Нагадування: бракує карток чи фактів, стан не зберігався 5 хв, налаштування не підтверджене, після стопу немає підсумку у вікні |
| `@@STATUS ...` | Стан запису; `@@STATUS stale`, коли записувач перестав оновлювати `status.json` |
| `@@NOW HH:MM:SS` | Час Мака на цьому опитуванні |

### Формат транскрипту

`<папка проєкту>/live/<YYYY-MM-DD-HHMM>-<назва>.md`:

```
# Live transcript: Status sync

- Проєкт: acme-portal
- Початок: 2026-10-10 23:48:02
- Мови: Я = en, дозволені = en+es
- Мікрофон: системний вхід за замовчуванням (навушники або Мак)
...
[23:48:11] Я (en): Can you hear me?
[23:48:15] Співрозмовник (es): Sí, perfecto.
[23:48:19] Співрозмовник [S2] (es): Empezamos con el reporte.

--- кінець запису 00:31:40 ---
```

З увімкненим розпізнаванням спікерів рядки співрозмовників мають мітку голосу (`[S2]`);
файл лише дописується, а на стопі записувач пише `<назва>.named.md` з іменами, які ти дав.
Поруч із транскриптом лежать робочі файли дзвінка: `<назва>.brief.md` (Live Brief),
`<назва>.cards.json` (миттєві картки), `<назва>.facts.json` (книга фактів),
`<назва>.state.json` (зсуви читання, статистика опитувань і власні ключі скіла: видані
підказки, відповіді, action items), `<назва>.polls.jsonl` (кожне опитування),
`<назва>.tips.jsonl` і `<назва>.inbox.jsonl` (вікно), `<назва>.speakers.json` і
`<назва>.semantic.jsonl` (коли ці шари увімкнені).

## 3. Вимоги

- Мак на Apple Silicon (M1 і новіші), macOS 14.2 або новіша.
- Xcode Command Line Tools (`xcode-select --install`; якщо їх немає, `install.sh` сам
  запропонує).
- Python 3.10+ (`brew install python@3.12`).
- ~2.5 ГБ вільного місця (модель + venv). Необов'язково: ~30 МБ на розпізнавання спікерів,
  ~1.2 ГБ на Ollama з `bge-m3` (смисловий шар). 16 ГБ пам'яті вистачає на все разом
  (розділ 5, "Локальний смисловий шар").
- Claude desktop (Cowork) з підключеною папкою, у якій лежать інструмент і папки проєктів
  (у автора `~/work`).
- Плагін `pm-control-tower` з конфігом проєкту в `projects/<slug>.md`. Скіл бере звідти
  команду, мітинги, `Local Paths` і Notion ID (`meetings_db`, `project_page_id`,
  `workspace_page_id`).
- Конектор Notion у Cowork (для Live Brief і сторінки в Meetings DB). Без нього підказки
  працюють, але без контексту з Notion і без сторінки після дзвінка.

1. **Покласти інструмент на Мак.** Скопіюй `tools/live-transcriber/` з цього репозиторію в

5a. **Плагін-запобіжник (рекомендовано).** Встанови `tools/live-tips-keepalive` як плагін

## 5. Як провести дзвінок

### 5.0 Перед дзвінком: модель і підготовка

**Яку модель обрати для сесії.** Кожна секунда роздумів моделі додається до затримки
підказки, тому вибір залежить від дзвінка:

| Дзвінок | Модель | Чому |
|---|---|---|
| Звичайні синки, стендапи, статуси | Sonnet 5.5, low або medium effort | Встигає за розмовою і досить уважна для перевірки відповідей |
| Інтерв'ю з клієнтом, ескалація, steering, важкі переговори | Opus 5.5 | Глибше бачить суперечності й недомовки; затримка 10-30 с на таких дзвінках прийнятна |
| Haiku | не рекомендовано | Занадто поверхово для перевірки відповідей і нюансів кількох мов |

**Підготовка в тій самій сесії.** Найкраще працює так: відкрити сесію в проєкті Cowork,
спершу зробити prep, а безпосередньо перед дзвінком написати `live tips`.

1. Prep: `client-meeting-prep` або `daily-team-prep`, чи вільний запит на кшталт
   "підготуй мене до інтерв'ю з клієнтом про звіти по транзакціях, візьми в першу чергу
   сторінки Notion <посилання> і папку <шлях>". Деталі мітингу, цілі, питання, сторінки й
   папки, які варто взяти в контекст першими, пишеш тут.
2. Перед дзвінком: `live tips <проєкт>`. Скіл бачить усе, що підготовлено раніше в сесії,
   і будує Live Brief довкола цього: цілі й питання з prep стають чеклістом, вказані
   сторінки й папка стають основою карти тем. Це пріоритет, а не обмеження: решта
   контексту проєкту (рішення, ризики, трекер, минулі мітинги) теж підтягується і
   використовується, коли розмова йде вбік.

**Вступне слово і "твоя черга".** Під час старту скіл заздалегідь готує "Мій апдейт":
3-4 пункти за пріоритетом (зроблено, в роботі, блокери чи потрібне рішення, далі) і готове
перше речення. Бере їх з prep-звіту на цей мітинг у Reports DB (той, що генерує скедулена
таска, наприклад `daily-team-prep`, або зроблений раніше в сесії) і з трекера. Для мітингу
по кількох проєктах, як-от внутрішній ПМ-синк, буде рядок на проєкт.

- **Починаєш ти** (ти ведеш мітинг, сказав про це, або перші 30 с з того боку тиша): одразу
  після чекліста приходить вступ: привітання, мета мітингу одним реченням, порядок тем або
  твій апдейт.
- **Тебе кличуть:** коли хтось звертається на будь-яке ім'я з `settings.user.name_aliases`
  (наприклад "Mike", "Michael", "Mikey", включно з кривим написанням від Whisper) з
  проханням розповісти апдейти, приходить підказка 🔴 "Твоя черга", без жодних лімітів
  частоти. У ній перше речення і пункти в порядку, в якому їх казати. Якщо питали про одну
  тему, буде лише ця тема.

> **🔴 Твоя черга: апдейт**
> "Коротко по Acme: все за планом, одне питання."
> 1. Звіт по транзакціях на тестуванні
> 2. Оплати: чекаємо відповідь клієнта
> 3. Потрібне рішення: дата релізу

**Перемикання мови посеред дзвінка.** На внутрішніх дзвінках можлива і українська, і
англійська. Твій мікрофон розпізнається лише серед твоїх мов (`me_langs`,
наприклад українська й англійська), тому українська не перетвориться на російську, а
англійська вставка розпізнається правильно. Скіл тримає "мову моменту": якщо тебе просять
"розкажи це англійською" або гість питає англійською, одразу приходить підказка з суттю
українською і фразою вже англійською, і далі фрази йдуть англійською, поки ти не
повернешся до української. Російської свідомо немає в наборах мов: російська фраза
записується українською. Додай `ru` у `langs`, лише якщо дзвінок справді цього потребує.

> **🟠 Тепер англійською: статус релізу**
> "Short update in English. The release is on track for Friday."

**Зустріч: аудиторія, тип, режим.** Від 1.8.0 дзвінок описують два налаштування, обидва за
замовчуванням `auto`, тож нічого не треба вибирати, щоб дзвінок був корисним. Виправляються
в меню ⚙ у вікні (Call) або словами в запиті.

| Налаштування | Значення | Що змінює |
|---|---|---|
| Аудиторія | `auto`, `team`, `client`, `boss` | Хто з того боку. `team`: свої люди, відверто, за замовчуванням українською, без виправлень тебе на дзвінку. `client`: англійською або мовою клієнта з конфігу, суворі правила 🔒, культурна лінза, перевірка відповідей. `boss`: внутрішній проєкт, де клієнтом виступає твій керівник: клієнтські правила для формулювань і зобов'язань, за замовчуванням українською, без культурної лінзи. `auto` береться з твоїх слів, потім зі слоту розкладу мітингів у конфігу, потім з конфігу проєкту, і виправляється за мовою та іменами, які звучать |
| Тип | `auto`, `presentation`, `interview` | Вибору потребують лише два окремі типи, бо їм потрібна своя підготовка: презентація отримує план і трекер Now/Next, співбесіда потребує ролі (нижче). Усе інше (статус, стендап, синк з клієнтом, глибоке обговорення однієї теми) це `auto` |
| Режим | `presenting`, `discussion` | Ніколи не питається, визначається на ходу. Коли ти говориш більшу частину останніх 2+ хвилин, ти доповідаєш, і приходять лише 🔴, 📌 факти і прямі відповіді; інакше звичайне обговорення |

Окремого типу "working session" більше немає: будь-який дзвінок може ним стати. Коло апдейтів
закривають твій спіч і підказка "твоя черга". Коли стендап ведеш ти, смуга agenda показує,
кого ще вислухати, а підказки пропонують уточнення на розмиті апдейти і власників та дати,
які треба зафіксувати.

**Інтерв'ю** (тип `interview`), обери роль. **Observer**: інтерв'юють іншого, ти бачиш, що
містить сильна відповідь, а потім рядок ✓ / ~ / ✗ про відповідь. **Coach** (коуч,
питають тебе; значення `coach`, старе `candidate` теж працює): керівний комітет, питання після
демо, квартальний огляд, аудит або репетиція перед будь-чим із цього. Як тренер біля бровки:
короткі підказки під час гри, а грає людина сама. Він тримає під рукою твої підготовлені тези,
цифри й результати, нагадує частину питання, на яку ти ще не відповів, і допомагає відповісти
коротко і за структурою. Бере лише те, що ти підготував (документ з тезами у твоїй Knowledge
Base: ключові меседжі, цифри, результати, заготовлені відповіді), і ніколи не вигадує фактів; без проєкту
дзвінок лягає у твій особистий Workspace. **Interviewer**:
уточнювальні питання на слабкі відповіді і заплановані питання, які ще не прозвучали. Після
дзвінка: повний аналіз (таблиця відповідей, сильні сторони, прогалини, сигнали, рекомендація,
як працював суфлер).

**Клієнтські дзвінки: культурна лінза і перевірка відповідей.** З аудиторією `client` і
розділом `## Cultural Profile` у конфігу проєкту підготовка додає до брифу коротку культурну
лінзу (де наша культура і культура клієнта різняться найбільше і як читати кожного
учасника). Готові фрази йдуть за нею (м'якша незгода з клієнтом, який говорить непрямо,
коротко і прямо з тим, хто говорить прямо), а пом'якшена скарга ("a bit concerning") чи
зміна тону з'являється як сигнал 🟠. Перевірка відповідей (чи відповів ти на питання, чи
правильні факти, чи не пообіцяв того, що не в твоїй владі) працює на дзвінках з клієнтом і
з шефом; на дзвінках команди вона мовчить, бо там ти думаєш уголос.

**Проактивні підказки за замовчуванням вимкнені.** Моменти для коментаря ("можеш
додати ...") та ініціативні підказки мали найгірші оцінки на реальних дзвінках ("ми не про
це говорили"). Від 1.8.0 за замовчуванням діє правило "факти або тиша": відповіді на
питання, факти до живої теми, "зафіксуй власника і дату", "твоя черга" і червоні прапорці.
Проактивні підказки вмикаються в ⚙ Call, коли вони потрібні (`tips.proactive` у
`settings.yaml`).

**Коли питаєш ти.** Будь-який дзвінок може перемикатися між "питаєш ти" і "питають тебе".
Скіл помічає відрізки, де питаєш ти, відстежує заплановані питання (поставлене, з
відповіддю, частково) і підказує, де відповідь розмита. У підсумку твої питання з
відповідями.

**Підготовка наперед і коли запускати.** Перед важливим дзвінком напиши будь-коли "підготуй
live tips до <дзвінок>". Скіл у субагенті читає всі джерела (мітинги, треди, теми, рішення,
ризики, звіти, трекер, документи проєкту, найновіші файли в теці проєкту, `live/lessons.md`)
і зберігає бриф, миттєві картки і книгу фактів. На старті підготовка, молодша за 3 години,
підхоплюється (`lt prep-check --adopt-prep`), тож факти є з першої секунди. Без підготовки
запускай за хвилину до дзвінка чи вже на ньому: запис стартує одразу, бриф збирається за
перші 1-3 хвилини, і свіжий можна попросити будь-коли (⚙ Context, Refresh, або "онови
контекст").

**Яка підготовка підхоплюється.** Лише та, чия назва збігається з назвою дзвінка. Збіг
ігнорує регістр, пробіли і дефіси, і одна назва може містити іншу: "Weekly Standup" збігається з
`prep-...-acme-weekly-stand-up`. Підготовка до іншого дзвінка ніколи не береться, тож її бриф і
внутрішні факти не потраплять не в ту зустріч. Давай підготовці і дзвінку однакову назву.

**Підготовка готова, лише коли є файли.** Збір контексту, що повернув гарний підсумок, але
без `cards.json` і `facts.json`, не дав нічого миттєвого. Тому він вважається завершеним,
лише коли `lt prep-check "<транскрипт>"` друкує `verdict: OK` (бриф, картки, факти, а для
презентації ще план є і коректні). На `FIX` скіл запускає `--fix` (картки з фактів) і
дописує решту між опитуваннями; доти `read_delta` друкує `@@DUE prep`.

### 5.1 Під час дзвінка

1. За хвилину до дзвінка напиши в Cowork: **`live tips <проєкт>`** (або "лайв підказки",
   "я на дзвінку", "дзвінок почався"). Якщо проєкт не названий, скіл спитає. Мову і
   тривалість можна дописати: "live tips acme, внутрішній, українською, 30 хв".
2. Скіл запускає `lt start`: той перевіряє, що інструмент встановлений, підхоплює запис того
   самого дзвінка, відмовляє, якщо пишеться інший проєкт (`BUSY`), кладе
   `control/start.json` і чекає `recording` (5-20 с на завантаження моделі). Вікно Terminal
   "Live transcriber" відкривається само: запускати його не треба. Запис живе саме в ньому,
   бо дозволи macOS на мікрофон і системний звук видані Terminal. Вікно можна згорнути
   (Cmd+M) або сховати за іншими, але не закривати. Якщо все ж закрити, запис акуратно
   зупиниться, а вже записаний транскрипт залишиться.
3. У чаті з'являється `Запис іде: <файл>. Мови: я en, дозволені en+es.` з визначеними
   аудиторією і типом, твій спіч з'являється у вікні за ~30-40 с, а за хвилину-дві рядок
   джерел (який Current State і які документи використано), чекліст мітингу з Live Brief
   (відкриті теми, рішення, ризики, обіцянки з минулих мітингів, тікети) і
   `Підкажу, коли буде що додати.`
4. Далі скіл говорить лише тоді, коли спрацьовує тригер, і лише з фактом. Тиша теж
   відповідь: загальна підказка гірша, ніж жодної.

| Рівень | Коли |
|---|---|
| 🔴 одразу | Пряме питання до тебе; "твоя черга"; прохання, схоже на нову вимогу; ти називаєш дату чи оцінку; суперечність ухваленому рішенню; сигнал незадоволення; на дзвінках з клієнтом і з шефом ти сказав факт, що суперечить трекеру чи рішенням |
| 🟠 щойно готова | Факт до теми, яку обговорюють саме зараз (з брифу, карток чи книги фактів); рішення, власник чи дата прозвучали, але не зафіксовані |
| 🟠 не частіше ніж раз на `active_rate_seconds` | Питання без відповіді ~2 хв; співрозмовники перейшли на іншу мову (коротка суть); 2/3 часу і непокриті пункти; 5 хв до кінця і неотримані рішення |
| 🟠 лише з проактивними, не частіше ніж раз на `comment_rate_seconds` | Моменти для коментаря та ініціативні підказки (`references/proactive.md`) |
| тихо | Action items, нові вимоги, зобов'язання: потрапляють у підсумок |

**Швидкий старт.** За замовчуванням (`start.mode: window`) у чаті питається лише те, що
визначає, куди піде запис: проєкт, якщо ти його не назвав, або компанія для твоєї власної
співбесіди. Решта стартує з `auto` чи налаштувань за замовчуванням, і ти виправляєш її в
меню ⚙ у вікні: мова і мікрофон перемикаються одразу без втрати транскрипту, аудиторія, тип
і твоя роль на співбесіді перебудовують підготовку. `start.mode: chat` лишає стартові
питання в чаті. Скерувати можна й одним рядком у будь-який момент: формат ("обговорення",
"моя доповідь", "з шефом") і куди дивитись ("дивись епік X", "тред про Y").

**Старт з очікуванням: відкрий вікно до дзвінка.** Стартуй за кілька хвилин (`"standby": true`
у `lt start`; у застосунку **Recording starts: When the call begins**). Вікно-суфлер
відкривається одразу, але поки ти чекаєш, нічого не розпізнається і не пишеться, і
попереджень про мікрофон немає (`state: standby` у `status.json`). Запис стартує сам, коли інша
сторона говорить приблизно 5 секунд (`standby_auto_s` у `config.json`), або одразу, коли ти
тиснеш зелену **Start** у вікні (чи `touch control/go`). Твій власний голос у кімнаті його не
запускає. Останні 20 с, почуті перед перемиканням, розпізнаються, тож перше речення не
губиться, а в транскрипті з'являється позначка `--- дзвінок почався ---`.

**Оновлення контексту посеред дзвінка.** Для несподіваного дзвінка або коли розмова пішла в
тему, якої немає в брифі: тисни ⚙ Context, Refresh, або пиши "онови контекст" / "refresh context" / "глянь
треди по X". Субагент перечитує джерела разом з темами останніх 10 хвилин, бриф і картки
оновлюються, а скіл наздоганяє все сказане за цей час: 1-3 хвилини без нових фактів, нічого
не губиться.

**Цикл не має замовкати.** Підказки є, лише поки триває хід Claude. Скіл не завершує хід
текстовою відповіддю під час дзвінка, плагін-запобіжник (розділ 4) блокує це механічно, а
вікно показує червоне попередження "Claude is not listening" після 75 с без опитування:
тоді напиши "continue" у чат Cowork. Скіл бере довжину перерви з `lt state`, каже, скільки
вона тривала, і наздоганяє пропущені рядки. `read_delta` і сам підганяє скіл: `@@DUE state`,
коли стан не зберігався 5 хвилин, `@@DUE ack` для непідтвердженого налаштування,
`@@STATUS stale`, коли записувач перестав оновлюватися.

### Вікно-суфлер

Щоб не дивитись у вікно Cowork під час дзвінка, підказки показує окреме маленьке вікно
поверх усіх інших. Його відкриває сам записувач на старті запису, вгорі по центру екрана,
під камерою.

Будова від 1.8.0, згори донизу (на кожному елементі є підказка при наведенні):

- **Верхня смуга:** точка запису, назва дзвінка, таймер, твоя частка розмови, `🎙` вимкнути
  мікрофон і `⚙` (одне меню для всього іншого). Поки підказки на паузі, видно маленьку
  позначку "Tips paused".
- **Рядок "хто говорить"** під нею (з увімкненим розпізнаванням спікерів): `🗣 Sarah` або
  `🗣 Speaker 2`. Клік по ньому дає перейменувати спікера, віддати один рядок іншій людині
  ("цей рядок сказав хтось інший") або злити двох спікерів в одного. Схований, коли говориш ти
  або ніхто.
- **Одне місце для попередження:** лише найважливіше за раз, з кнопкою дії, де вона
  допомагає: "Use Mac mic", коли мікрофон навушників завис, "Back to headset" після
  автоматичного перемикання, червоне "Claude is not listening".
- **Док:** agenda одним рядком з прогресом (клік розгортає пункти з ✓ / ○; на співбесіді
  питання, на стендапі, який ведеш ти, люди), Now/Next у презентації, далі закріплені картки:
  📌 на будь-якій підказці закріплює її, закріпити можна і спіч, чекліст, статус і підсумок.
  Відкріплена картка повертається на своє місце в списку.
- **Підказки:** найновіша зверху великим шрифтом, попередні нижче, тьмяніші.
- **Нижній ряд:** одне поле вводу, `⏸` / `▶` і `🆘`, плюс кнопки-питання (нижче).
- **`🎙` мьют.** Записувач слухає мікрофон Мака і не бачить, чи ти замьючений у Meet або Zoom:
  стан кнопки мьюту в програмі для дзвінків ззовні не прочитати, а помилкова здогадка тихо
  губила б твої слова, тому кнопка ручна навмисно. Навіщо вона: у кафе, з музикою чи людьми
  поруч ти замьючений у зустрічі, але мікрофон усе одно чує кімнату, і Whisper записав би це
  так, ніби це сказав ти. Що робить кнопка: стає червоною (`🔇`), записувач перестає
  розшифровувати мікрофон (співрозмовників і далі записує), у транскрипті з'являються рядки
  `--- мікрофон вимкнено HH:MM:SS ---` і `--- мікрофон увімкнено HH:MM:SS ---`, у статусі
  `mic=muted`, а скіл не вважає твою тишу проблемою і не робить перевірку відповідей за цей
  час. Тисни ще раз, коли розмьютишся. Кожен дзвінок починається з увімкненим мікрофоном.
- **Поле вводу.** Поки пишеш, вікно одразу шукає в книзі фактів на Маку, без моделі:
  відповідні факти з'являються під полем. Enter надсилає текст Claude як питання
  (`find: <слова>`, коли локальний пошук нічого корисного не знайшов: тоді Claude шукає в книзі
  фактів, в індексі проєкту й одним вузьким запитом і дописує факт у книгу). "стоп" у полі
  зупиняє дзвінок так само, як у чаті.
- **`⏸` / `▶` пауза підказок.** Розмова пішла вбік (світська балачка, стороння тема)? Тисни
  `⏸`: записувач далі пише і розпізнає, скіл далі слухає і записує action items, але нічого
  автоматичного не з'являється: ні миттєвих карток, ні 📌 автофактів, ні позначок ❓, картки
  "Who is speaking?" чекають у черзі. Поле вводу, 🆘 і відповіді на твої питання працюють.
  `▶` продовжує з живої теми останніх ~2 хвилин, а не з місця, де підказки зупинились.
- **`🆘` HELP NOW.** Для моменту, коли ти говориш і не можеш писати. Одразу, без моделі,
  записувач показує найкращі факти й картки до теми останньої хвилини (за змістом зі
  смисловим шаром, за ключовими словами без нього) і до 2 уривків з папки проєкту. Потім
  Claude надсилає одну 🔴 підказку з наступним реченням, яке можна сказати просто зараз:
  відповідь на відкрите питання, факт з числом або місток ("Let me give you the exact number
  after the call."). Жодні ліміти частоти на неї не діють.
- **Позначка питання ❓.** Коли співрозмовник щось питає, записувач одразу позначає це у вікні
  (`❓` і перші слова питання); відповідь Claude потім займає її місце. З 2026-10-22 вона
  буває лише на справжніх робочих питаннях: рядок, що називає тебе і питає, рядок з робочим
  словом (оцінка, дедлайн, статус, ціна, реліз...) або питання про час чи кількість ("коли...?",
  "скільки...?"). Пісні, балачки і самотній "?" її не дають.
- **Кнопки-питання** біля поля: **Suggest reply** (готова відповідь чи коментар по поточній
  темі), **Catch me up** (останні ~5 хвилин у 3-5 рядках), **Decided so far** (рішення й
  задачі з власниками і датами), **What to ask now** (1-2 питання по відкритих пунктах).
  Відповіді з транскрипту, без пошуків, за кілька секунд.
- **Меню ⚙**, п'ять частин:
  - **Call:** тип, роль на співбесіді, аудиторія, мова, мікрофон, проактивні підказки (і їхня
    частота, коли увімкнені). Мову і мікрофон записувач застосовує одразу (у транскрипті
    з'являється рядок `--- мова ---` / `--- мікрофон ---`); решта йде скілу і показується як
    очікувана, доки скіл її не підтвердить.
  - **Display:** повзунок розміру тексту (також Cmd+ і Cmd-), прозорість (блідне лише фон: текст лишається непрозорим з
    м'яким ореолом і читається навіть на низькій прозорості), поверх усіх вікон,
    мова інтерфейсу (за замовчуванням англійська, або українська), невидимість (нижче) і
    перемикач "Local AI (Ollama)" (смисловий шар на цей дзвінок увімкнено чи вимкнено).
  - **Context:** "Brief from HH:MM" і Refresh (оновлення контексту, вище).
  - **Diagnostics:** те, що раніше показував рядок стану: стан запису, кількість рядків,
    затримки, попередження.
  - **Help:** пояснення кожної кнопки і опції прямо у вікні.
- **Мова інтерфейсу.** За замовчуванням англійська; українська вмикається в ⚙ Display. Суть
  підказки йде за нею: українською, коли інтерфейс або дзвінок український, інакше
  англійською. Готові фрази завжди тією мовою, якою від тебе чекають відповіді. Кнопки-питання
  доходять до скіла англійською, хоч би яка мова інтерфейсу.
- **⚡ Миттєві картки.** Підготовка пише 15-40 карток (фрази-тригери всіма мовами дзвінка і
  готова підказка) у `<транскрипт>.cards.json`. Записувач сам звіряє кожен новий рядок (за
  ключовими словами, а зі смисловим шаром і за змістом) і показує картку за 1-2 с, ще до
  того, як Claude подумає; Claude потім лише доповнює те, чого картка знати не могла.
- **✓ / ~ / ✕ на кожній підказці.** Використав, частково, не до місця. Після ~ чи ✕ вікно
  пропонує причини (late, off topic, wrong fact, too long, not now) і короткий коментар. Скіл
  діє за причиною: хибний факт одразу перевіряє і виправляє, "too long" робить такі підказки
  коротшими, два "off topic" вимикають картку до кінця дзвінка. 🔴 підказки і 📌 факти ніколи
  не глушаться. Підсумок усе це рахує.
- **Затримка на виду.** На кожній підказці видно, через скільки після фрази вона з'явилась
  ("+18s", помаранчеве понад 20 с); Diagnostics показує медіану і "transcript N s behind",
  коли розпізнавання відстає. Підказка, що прийшла, коли ти вже почав відповідати,
  показується тьмяною і йде в аналіз уроків.
- **Лічильник розмови** у верхній смузі: твоя частка часу і поточний монолог (помаранчевий
  після 1:30).
- **Вікно звичайне:** його можна перетягнути, змінити розмір, згорнути (жовта кнопка або
  Cmd+M) і закрити (червона кнопка або Cmd+W). Закриття вікна запис не зупиняє. Позицію і
  розмір воно запам'ятовує.
- **Закрив випадково?** Напиши в чат "відкрий суфлер" або в Terminal
  `touch ~/work/Tools/live-transcriber/control/prompter`. За секунду вікно відкриється знову
  з усіма підказками від початку дзвінка.
- **Невидимість і демонстрація екрана.** ⚙ Display, невидимість (Stealth) за замовчуванням
  увімкнена: вікно просить macOS не потрапляти в показ екрана і знімки екрана
  (`sharingType = none`). Вимкни її, коли хочеш показати вікно колегам або зняти його на
  знімок. Перемикач потребує вікна, зібраного версією 1.8.0 (після оновлення перезапусти
  `install.sh`). Чи слухається невидимості конкретна програма для дзвінків, залежить від того,
  як вона захоплює екран, тому перевір один раз сам (розділ 10). **Перевірено 2026-10-11:**
  Google Meet у Chrome на macOS 26, демонстрація всього екрана, вікна в показаному зображенні
  немає. Для інших програм (Zoom, Teams) не перевірено. Якщо сумніваєшся: показуй не весь
  екран, а окреме вікно чи вкладку.
- **Куди йдуть підказки** задає `tips.output` у `settings.yaml`: `window` (так у шаблоні),
  `chat` або `both` (коли ключа немає). Чат лишається запасним варіантом.
- **Демо без дзвінка:** `python3 ~/work/Tools/live-transcriber/bin/demo_prompter.py`
  відкриває справжнє вікно зі сценарієм дзвінка (близько 2 хвилин). `bin/prompter --demo`
  показує лише три статичні підказки.

Технічно: скіл дописує підказки рядками JSON у `<транскрипт>.tips.jsonl`, вікно їх
показує; питання з поля вікно пише в `<транскрипт>.inbox.jsonl`, а `read_delta.py`
повертає їх скілу як `@@ASK`. Налаштування, оцінки, 🆘 і ⏸ ідуть тим самим шляхом і
приходять як `@@SET` і `@@SOS`.

### Розділений вигляд для презентації

З типом зустрічі **Presentation** і підготовкою зі слайдами (`<stem>.slides.json`, його пише
підготовка презентації поруч з outline) вікно-суфлер стає вдвічі ширшим і ділиться на 2
половини: картки слайдів з повним текстом твого виступу і звичайна стрічка підказок. Скіл і
застосунок поводяться однаково.

- **Один слайд за раз.** Картки стають на місце по одній; гортай стрілками на клавіатурі,
  кнопками ◀ ▶ або коліщатком миші.
- **Таймер.** Вкажи ліміт у хвилинах: запланований час кожного слайда масштабується під нього.
  Рядок темпу показує слова за хвилину (повільно, норм, швидко).
- **Авто** перегортає картки за розкладом з коротким сигналом і попереджає за 10 с до кінця
  слайда. Вимкни, щоб гортати вручну.
- **Стиснути** ховає абзаци з позначкою "можна пропустити", коли не встигаєш.
- **Мої слайди / Усі слайди.** Коли виступають кілька людей, показує лише твою частину або всю
  презентацію.
- **Типи абзаців** на картці: читати вголос; можна пропустити (блідий, з позначкою); підказка
  для тебе, не читати (дрібна, сіра); репліка колеги просто перед твоєю частиною (помаранчева),
  щоб знати, коли починати.
- **План і факт.** Наприкінці таблиця порівнює запланований і фактичний час кожного слайда.
- **📑** ховає або показує картки, **⇄** міняє 2 половини місцями (запам'ятовується між
  дзвінками). Вікно росте в бік карток, тож стрічка підказок лишається там, де ти її поставив.

### Розпізнавання спікерів (необов'язково)

У системному каналі всі співрозмовники разом, тож без цього шару всі вони `Співрозмовник`.
Зі встановленим `bin/install-voices.sh` записувач розрізняє голоси на Маку (sherpa-onnx з
моделлю голосу WeSpeaker), а імена даєш ти.

- **Групи голосів.** Кожна фраза від 1 с отримує відбиток голосу в окремому потоці. Фраза
  приєднується до найближчого спікера, новий голос відкриває `Speaker 1`, `Speaker 2`, ...
  Рядки в транскрипті отримують мітку (`Співрозмовник [S2] (es): ...`).
- **"Who is speaking?"** Після ~8 с мовлення нового голосу картка питає ім'я, з останньою
  цитатою і її часом. Пропозиції беруться з твоєї локальної бібліотеки голосів (люди, яких ти
  називав на попередніх дзвінках, з точкою збігу) і з людей проєкту (повні імена з конфігу).
  Вибери, напиши ім'я або Skip. **Ім'я ніколи не ставиться автоматично:** вирішуєш ти, скіл
  не вгадує.
- **Виправлення на ходу.** Рядок "хто говорить" відкриває перейменування, "цей рядок сказав
  хтось інший" і злиття (одна людина розпалась на двох спікерів). Кожна зміна діє на весь
  дзвінок, на минулі й наступні рядки.
- **Нічого не гальмує.** Рядок і підказка ніколи не чекають спікера: мітка голосу може
  прийти на кілька секунд пізніше за рядок, і скіл отримує її як `@@SPEAKERS`. Підказки,
  action items і підсумок вживають імена, коли вони відомі.
- **Після дзвінка** записувач пише `<назва>.named.md`, транскрипт з іменами (оригінал не
  змінюється), а підсумок рахує рядки кожної людини.
- **Де лежать відбитки голосу:** лише на цьому Маку, у `<tool_root>/voices/voices.json` (до
  20 відбитків на людину). Ніколи не клади `voices/` у репозиторій. Про приватність у
  розділі 11.

Пороги і як їх підбирали: README інструмента, "Розпізнавання спікерів".

### Надійність мікрофона

Мікрофон навушників може зависнути без жодного сигналу від macOS, зазвичай одразу після того,
як ти розмьютився в Meet: звук не приходить зовсім, і дзвінок іде без твоїх слів. Від 1.8.0
записувач за цим стежить:

- **Сторож.** Немає звуку мікрофона 12 с, або 10 с лише цифрові нулі, коли ти не замьючений,
  це зависання. Записувач перезапускає `audiocap` (спершу зупиняє, потім вбиває), між
  спробами чекає дедалі довше, до 60 с, і ніколи не здається. Відновленням вважається лише
  справжній звук після перезапуску.
- **Автоматичне перемикання.** Після 2 невдалих перезапусків поспіль він перемикається на
  мікрофон самого Мака (`--- мікрофон: перемкнув на мікрофон Мака ---` у транскрипті).
  Попередження у вікні пропонує "Back to headset"; поки мікрофон завис, пропонує "Use Mac
  mic".
- **Прямий запис (2026-10-22).** Деякі USB-навушники і донгли не віддають стандартному аудіодвигуну
  macOS (AVAudioEngine) жодного звуку, а старт міг на цьому зависнути. Тепер `audiocap` читає пристрій вводу
  напряму, коли двигун не дає кадрів (`--mic-backend direct`), а записувач стартує мікрофон раніше
  за перехоплення системного звуку, бо одночасний старт міг повісити мікрофон.
- **Сторож старту.** `audiocap`, що завис на старті (наприклад, на запиті дозволу, на який
  ніхто не відповів), зупиняється після тайм-ауту і стартує знову, щоб запис не стояв мовчки.
- **Одна позначка на епізод.** У транскрипті з'являється один рядок `--- мікрофон завис ---`
  на епізод і `--- мікрофон відновився ---`, коли звук повернувся, а не рядок на кожну
  спробу. Скіл надсилає одне 🔴 "Мікрофон не пишеться" і одне "Мікрофон повернувся" і ніколи
  не стверджує, що ти ще не говорив, поки мікрофон висів чи був вимкнений. Підсумок перелічує
  перезапуски і хвилини твого мовлення, які могли загубитись.

### Локальний смисловий шар (необов'язково)

Підказки за ключовими словами працюють і без нього. З локальною моделлю векторів (Ollama з
`bge-m3`) записувач розуміє й перефразування українською, англійською та іспанською:
"скільки займе історія адмінки?" знаходить факт "Журнал дій адміністратора: 16 год".

- **Під час дзвінка:** факти й картки спрацьовують за змістом, а не лише за ключовими
  словами; 🆘 HELP NOW добирає факти за темою останньої хвилини плюс 1-2 уривки з індексу
  проєкту; пошук `find:` і `lt search` шукають у файлах проєкту. Кожен рядок обробляється в
  окремому потоці з коротким тайм-аутом: розпізнавання і підказки на нього ніколи не чекають.
- **Індекс проєкту.** `lt index "<папка проєкту>"` переводить у вектори текстові файли
  проєкту (`.md`, `.txt`, `.csv`, невеликі `.json`), разом з локальною копією Notion
  (`_notion/`), у `<проєкт>/.livetips-index/`. Він дописується поступово (лише нові чи
  змінені файли), а під час дзвінка записувач індексує свіжі файли у фоні, лише коли
  розпізнавання простоює. Пропускаються: `.git`, `repos/`, архіви, бінарні файли, файли понад
  2 МБ, робочі файли дзвінків (індексуються лише транскрипти) і все, що схоже на секрети
  (папки `secrets`, `.env`, назви з password, token, credential чи API key). Додай
  `.livetips-index/` у `.gitignore`.
- **Окремо на проєкт, а не на всю робочу папку.** Індекс на проєкт тримає клієнтів окремо
  (уривок з папки іншого клієнта ніколи не має виринути на дзвінку), лишається досить малим,
  щоб зібратися за хвилини, а не за години, і дає точніші збіги. Спільну папку можна додати
  через `--extra`.
- **Чи воно того варте?** Кожен збіг і майже-збіг пишеться з оцінкою в
  `<назва>.semantic.jsonl`, а підсумок додає один рядок з цифрами за дзвінок, тож ти сам
  бачиш на своїх дзвінках, чи це допомагає. Перемикач "Local AI (Ollama)" у ⚙ Display вимикає
  шар на дзвінок; коли Ollama не працює, шар `off` з причиною, а записувач пробує знову
  кожні 30 с.
- **Мак на 16 ГБ.** `bge-m3` займає приблизно 1.2 ГБ поруч із Whisper (приблизно 1.6 ГБ);
  дзвінок робить близько 7 коротких запитів на хвилину. Індексуй до дзвінка. Коли пам'яті
  бракує, постав `index_enabled: false` (без фонового індексування) або
  `semantic_enabled: false` у `config.json`.

Команди, пороги і формат індексу: README інструмента, "Смисловий шар (Ollama)".

### Як виглядає підказка

Розраховано на маленьке вікно Cowork вгорі по центру екрана, під камерою, щоб погляд не
бігав. Тому кожна підказка має 2-5 коротких рядків (до ~45 символів), без таблиць,
заголовків і посилань.

1. **Суть**, жирним: емодзі і що відбувається, до 7 слів. Завжди першим рядком, щоб за
   секунду зрозуміти, про що мова. Мова: українська, коли інтерфейс вікна або дзвінок
   український, інакше англійська.
2. **Фраза**, в лапках, мовою дзвінка. Це готова мова, яку можна прочитати вголос як є,
   а не тези. 1-2 речення. Англійською прості речення до 12 слів, побутова лексика, Present
   або Future Simple, активний стан, без ідіом і довгих підрядних.
3. **Факти**: до 3 рядків до 8 слів, з числами. Підказка несе одну фразу або один рядок
   факту; довше лише спіч, "твоя черга", agenda, catch me up і 🆘.
4. **Джерело**: один короткий рядок курсивом (тема і дата).

**Без абревіатур:** "нова вимога", а не CR, "термін", а не ETA. Ключів тікетів теж немає,
замість них назва теми. Імена людей і назви продуктів лишаються як є.

Приклади на англійському дзвінку з українським інтерфейсом (з англійським інтерфейсом суть та сама, але англійською):

> **🔴 Нова вимога. Не погоджуй зараз.**
> "Good idea. I will write it down. We will check it and come back to you."

> **🔴 Неточно: реліз 15.10, не 10.10**
> "Sorry, a small correction. The release date is October 15."
> _рішення від 30.09_

> **🟠 Питали про термін, не про обсяг**
> "About the date: I will confirm it with the team by Friday."

> **🟠 Між собою іспанською**
> Сумніваються, чи встигнуть протестувати до релізу.

На внутрішньому українському дзвінку і суть, і фраза українською.

Підказка з 🔒 спирається на внутрішнє джерело: її не можна повторювати клієнту вголос.
Оцінок у годинах скіл ніколи не пропонує: "оцінку дає виконавець, зафіксуй і повернись".

**Питання під час дзвінка.** Пиши в чат будь-що ("що ми обіцяли по X?", "який статус
ACME-123?"). Скіл відповідає коротко з брифу і транскрипту, потім продовжує слухати з
того самого місця. Якщо цикл зупинився, напиши "продовжуй".

## 6. Як завершити мітинг

Три рівноцінні способи. У кожному з них транскрипт закривається рядком
`--- кінець запису HH:MM:SS ---`.

1. **У чаті (звичайний шлях):** напиши `стоп`, `все`, `кінець`, `кінець дзвінка` або
   `end live` (або "стоп" у полі вікна). Скіл зберігає свій стан і запускає `lt stop`, який
   чекає до 60 с, поки дорозпізнаються останні фрази; потім читає останні рядки.
2. **У вікні Terminal** "Live transcriber" (воно відкрилось само на старті): Ctrl+C або
   закрити вікно. Це запасний шлях, якщо чат недоступний. Скіл побачить `stopped` на
   наступному опитуванні.
3. **Автоматично:** якщо після щонайменше 20 рядків `idle_stop_minutes` хвилин немає нових
   реплік, скіл один раз питає "Дзвінок закінчився? Зупиняю запис через 2 хв" і зупиняє.
   Жорстка межа: запланована тривалість + 20 хв або `hard_cap_minutes`.

Важливо: **закриття Zoom/Meet запис не зупиняє.** Інструмент далі слухає системний звук
(музику, відео). Треба один із трьох способів вище.

Вручну без скіла: `touch ~/work/Tools/live-transcriber/control/stop`.

## 7. Що відбувається після дзвінка

### 7.1 Підсумок у чаті (українською)

Action items (хто / що / коли), нові вимоги, наші зобов'язання, відкриті питання,
"Відповіді, до яких варто повернутись" (питання → що не так → як закрити), непокриті пункти
чекліста, шлях до транскрипту, посилання на сторінку в Notion. Люди названі так, як ти
назвав їх у вікні; неназвані голоси лишаються "Speaker N". Далі скіл лише пропонує наступні
кроки (звіт, change-request, risk-register) і нічого не запускає без команди.

Усі цифри беруться з `lt wrapup-data`, а не рахуються на око: рядки, мови і рядки кожного
спікера, показані підказки за видами, оцінки з причинами, спрацьовані картки, 📌 факти,
запізнілі підказки, затримки (медіана і максимум), найдовша пауза між опитуваннями,
перезапуски завислого мікрофона і один рядок про смисловий шар. Коротка підказка-підсумок
("Дзвінок завершено") завжди йде і у вікно; `read_delta` друкує `@@DUE wrapup`, доки її
немає. Клієнтські дзвінки додають сигнали клієнта (цитати з часом) для
`client-satisfaction-tracker`.

### 7.2 Сторінка в Meetings DB (автоматично)

**Без дублікатів.** Той самий дзвінок ти часто паралельно записуєш Notion AI Meeting Notes.
Тому скіл спершу шукає сторінку цього мітингу: посилання, яке ти дав, інакше нотатки Notion
AI, що почались у межах 20 хвилин від запису, інакше сторінки Meetings DB того ж часу
(повторний пошук через ~60 с: Notion AI буває доробляє сторінку пізніше). Знайшов: дописує в
кінець один розділ "Live Tips: підсумок і роздуми", що б уже не було на сторінці, ніколи не
змінює наявні блоки, додає свій транскрипт, лише якщо на сторінці його немає, і заповнює
`Project`, `Workspace`, `Date`, лише якщо вони порожні. Кілька кандидатів: питає, який саме.
Жодного: створює одну сторінку в `notion.meetings_db` проєкту:

| Що | Значення |
|---|---|
| Назва | `<згенерована назва> @<дата-час початку>`. Назву скіл складає з того, про що реально говорили (2-6 слів, мовою дзвінка). Дата-час у назві є Notion date mention, тобто клікабельною датою, як у нативних AI Meeting Notes |
| `Date` | Дата і час початку мітингу (`started_at` зі `status.json`, з часовим зсувом Мака) |
| `Project` | Сторінка проєкту (`notion.project_page_id`) |
| `Workspace` | Воркспейс, до якого належить проєкт: береться з relation `Workspace` на сторінці проєкту (запасний варіант `notion.workspace_page_id`). Приклад: проєкт належить воркспейсу компанії, у якій ти працюєш |
| `Meeting type` | Лише якщо тип мітингу точно збігається з наявною опцією; нові опції скіл не створює |
| `Summary` | 1-2 речення |
| Тіло | Блок AI Meeting Notes з транскриптом, під ним розділ "Підсумок" (action items як to-do, нові вимоги, відкриті питання) |

**Обмеження Notion API (перевірено 2026-10-11).** Секції `Transcript` і `Summary` блоку AI
Meeting Notes через API не записуються: специфікація Notion прямо каже, що запис у
`<transcript>` завершується помилкою. Генерацію саммарі Notion AI через API теж не
запустити. Тому:

- транскрипт кладеться в секцію **Notes** блоку AI Meeting Notes (по рядку на абзац);
- саммарі пише сам скіл (поле `Summary` і розділ "Підсумок");
- якщо хочеш саммарі саме від Notion AI, натисни Notion AI у блоці вручну.

Технічна деталь, щоб не наступити вдруге. `notion-create-pages` зберігає
`<mention-date …/>` у назві як звичайний текст. Тому скіл спочатку створює сторінку з
простою назвою, а потім ставить назву з датою через `notion-update-page`
(`update_properties`), який mention розпізнає. Після цього скіл перечитує сторінку і
перевіряє назву, поля і кількість рядків.

Якщо мітинг записувався через Notion AI Meeting Notes (fallback, розділ 8), друга сторінка
не створюється: справжній транскрипт уже є в Notion.

### 7.3 Уроки з твоїх нотаток

Усе, що ти пишеш під час дзвінка не як питання ("тут правильніше було відповісти так",
"такі підказки не треба", "запізно"), збирається разом з оцінками ✓ / ✕ і проблемами циклу.
Після дзвінка скіл показує два пронумеровані списки: **уроки проєкту** (ідуть у
`<тека проєкту>/live/lessons.md`, який кожна наступна підготовка цього проєкту читає першим
і перетворює на правила брифу й картки) і **зміни скіла** (проблема, зміна, де). Без твого
"так" нічого не змінюється; схвалені зміни скіла приходять карткою на збереження (або
пакетом `.skill`) плюс рядок у `Skills/live-tips-changelog.md`.

## 8. Fallback: Notion AI Meeting Notes

Якщо Мак офлайн або live-transcriber не стартує, увімкни запис у Notion AI Meeting Notes
і скинь скілу посилання на сторінку мітингу. Скіл читатиме транскрипт звідти. Підказки
будуть менш точні: у Notion немає міток спікерів, а українську мову він подекуди
перетворює на кострубату англійську. Для цього режиму є окремий скіл `notion-live-tips`
(у пакет не входить).

**Де лежить `settings.yaml`.** Це файл усередині скіла `live-tips` у твоєму акаунті Claude,
а не окремий файл на Маку. Щоб його змінити, правиш файл у папці скіла і завантажуєш скіл
заново (zip з папкою `live-tips/`, де лежать `SKILL.md`, папка `references/` і
`settings.yaml`; zip без `references/` дасть скіл, який повідомлятиме, що модуля бракує) у
налаштуваннях Claude, розділ Skills. У репозиторії шаблон лежить у
`plugin/skills/live-tips/settings.yaml`.

Тонкі параметри розпізнавання (`vad_mode`, `end_silence`, `max_segment`, вікно відлуння,
`lang_bias`, `gap_resync`)
лежать у `DEFAULTS` в `src/transcriber.py` і за потреби перевизначаються в `config.json`.
Там же налаштовуються необов'язкові шари: `speakers_enabled`, `speaker_join` (0.45),
`speaker_suggest` (0.5), `speaker_prompt_s` (8); `semantic_enabled`, `index_enabled`,
`semantic_fact_min` (0.55), `semantic_card_min` (0.60), `semantic_margin` (0.08). README
інструмента пояснює кожен.

## 11. Приватність і етикет

- Аудіо не зберігається: розпізнані фрази одразу дописуються в `.md`, аудіобуфери живуть
  лише в пам'яті.
- Транскрипти лежать у папці проєкту (`<проєкт>/live/`). Не додавай їх у публічні
  репозиторії.
- Сторінка в Meetings DB внутрішня. Скіл ніколи нічого не надсилає клієнту.
- **Відбитки голосу це біометричні дані.** Розпізнавання спікерів зберігає відбитки голосу
  людей, яких ти назвав (і клієнтів теж), лише на твоєму Маку в `voices/`; нікуди вони не
  йдуть. У багатьох країнах відбиток голосу вважається біометричними персональними даними,
  для яких потрібна правова підстава або згода. Попереджай учасників, дотримуйся правил своєї
  компанії і клієнта і не вмикай цей шар там, де не можна. Видали людину з
  `voices/voices.json`, коли просять; видали папку, щоб забути всіх. Ніколи не клади
  `voices/` у репозиторій.
- Смисловий індекс (`.livetips-index/`) і його журнали це локальні файли в папці проєкту;
  записувач говорить лише з Ollama на `127.0.0.1`. Секрети в індекс не потрапляють; тримай
  індекс поза git.
- Попереджай учасників, що ведеш транскрипт, як і з будь-яким записувачем. Вимоги до
  згоди різняться залежно від країни і договору з клієнтом.

### 13.2 Що зроблено тут

- **Помічник запису звуку** (`audiocap`, Swift): мікрофон і системний звук двома окремими
  потоками, перемикання пристроїв і сторожі: завислий потік перезапускається, старт, що
  завис, вбивається і повторюється, після кількох невдач запис перемикається на мікрофон Мака.
- **Конвеєр навколо Whisper** (`transcriber.py`): сегментація поверх VAD, фільтр шуму, фільтри
  вигаданих Whisper рядків (титри субтитрів, луна промпту, описи звуків), закріплені мови на
  дзвінок і на канал, формат транскрипту, лічильник часу мовлення.
- **Вікно-суфлер** (`prompter.html` + `prompter.swift`): розкладка, меню під шестернею, слот
  попереджень, закріплення, оцінки, 🆘 і пауза, картка спікера, приховування, дві мови
  інтерфейсу.
- **Протокол між записувачем і Claude:** `read_delta.py` (довге опитування, підказки у вікно,
  ввід із вікна, стан, нагадування) і помічник `lt` (старт, статус, стоп, перевірка
  підготовки, стан, цифри для підсумку, пошук).
- **Миттєві картки і книга фактів:** формати, локальне зіставлення, рядок питання і локальна
  реакція на 🆘, без моделі.
- **Розпізнавання спікерів поверх голосової моделі:** кластеризація на ходу, процес "Хто
  говорить?", виправлення і об'єднання, локальна бібліотека голосів, імена на весь дзвінок.
- **Семантичний шар поверх текстової моделі:** факти і картки за змістом, жива тема, індекс
  на кожен проєкт з виключеннями, логи користі.
- **Скіл** (`live-tips`): підготовка (бриф, картки, факти), правила на дзвінку (факт або тиша,
  пріоритети, тригери, формат підказки), підсумок у Notion і уроки.

## 14. Застосунок Live Tips (бета)

Нативний застосунок macOS у рядку меню, що крутить той самий цикл live tips без чату Cowork.
Код і деталі: [`tools/live-tips-app/`](../../tools/live-tips-app/README.md).

**Завантажити:**
[LiveTips-0.4.3-beta.dmg](https://github.com/bodco/pm-control-tower/releases/download/live-tips-app-v0.4.3/LiveTips-0.4.3-beta.dmg)

Що він робить:

- записує дзвінок на Маку і там же розпізнає його через MLX Whisper (те саме ядро записувача);
- звертається до Claude API напряму з твоїм власним ключем, що зберігається в Keychain macOS,
  на подіях (питання, твоє ім'я, нова вимога), а не через цикл у чаті, який може замовкнути;
- ліміти витрат: м'який і жорсткий на дзвінок і місячна стеля; на жорсткому ліміті працює лише
  локальний шар. Зазвичай $0.10-1.20 за годину дзвінка;
- вбудований локальний AI (`bge-m3`) для фактів і карток за змістом, 🆘 HELP NOW і пошуку по
  проєкту, Ollama не потрібна;
- старт з очікуванням, вибір мікрофона, який не зіскакує, коли macOS перемикає пристрої,
  розділений вигляд для презентацій і те саме вікно-суфлер;
- розпізнавання спікерів, як у скілі: картка "Who is speaking?" пропонує людей проєкту, імена
  потрапляють у підказки і підсумок, бібліотека голосів лишається на Маку
  (**Settings > AI > Speakers**).

**Це бета.**

- Ще не нотаризований: першого разу клацни по застосунку правою кнопкою, обери **Open** і
  підтверди.
- macOS 14.4 або новіша на Apple silicon.
- Python 3.10 або новіший. Вікно **Setup** перевіряє його і ставить решту (модулі Python,
  модель мовлення, модель локального AI; разом приблизно 2.5 ГБ), з галочкою біля кожного
  кроку. Пароль адміністратора не потрібен.
- Будуть шорсткості: повідомляй про них з рядками логів, ніколи з транскриптами.

### 14.1 Застосунок чи скіл

Обидва роблять приблизно одне й те саме: ті самі правила (застосунок і скіл читають одну
спільну папку `rules/`), "факт або тиша", те саме вікно-суфлер. Вибір за тобою.

| | Скіл у Cowork | Застосунок |
|---|---|---|
| Доступ до моделі | Твій план Claude, без API-ключа | Твій власний API-ключ Claude, оплата за використання |
| Під час дзвінка | Чат Cowork зайнятий увесь дзвінок | Нічого не треба тримати відкритим, один клік з рядка меню |
| Пошук контексту посеред дзвінка | Notion, трекер, файли проєкту через субагент | Контекст дзвінка, підготовка, локальний пошук по папці проєкту |
| Контроль витрат | Ліміти плану | Ліміти на дзвінок і на місяць у Settings |

Найкраще вони працюють разом. Підготовку роби в Cowork (бриф, картки фактів, outline і слайди
для презентації): застосунок підхоплює її сам, коли назва підготовки збігається з назвою
дзвінка (правило в розділі 5.0). У **Start call** натисни **Copy request for Cowork**, щоб
отримати готовий запит на підготовку. Без підготовки застосунок бере контекст дзвінка, який ти
вписав у Start call, поточний стан проєкту і локальний пошук по папці проєкту.

### 14.2 Після дзвінка: сторінка зустрічі в Notion

Коли в **Settings > General** увімкнено **Write the call summary to Notion**, застосунок сам
пише підсумок у Notion, щойно ти завершуєш дзвінок. Останній дзвінок можна надіслати і пізніше
з меню в рядку меню: **Send last call to Notion**.

1. Один виклик Claude робить із транскрипту і підказок підсумок: задачі з відповідальними і
   датами, рішення, твої зобовʼязання, нові вимоги (кандидати на зміну обсягу), відкриті питання
   і ризики.
2. Застосунок шукає сторінку цієї зустрічі в базі Meetings проєкту: сторінку, у якої `Date` не
   далі ніж 20 хвилин від початку дзвінка (сторінка Notion AI Meeting Notes, створена з
   календаря, теж підходить).
3. Знайшов: дописує в неї розділ **Live Tips**. Не знайшов: створює нову сторінку зі звʼязками
   на проєкт і workspace і справжньою датою в назві, як скіл.
4. Транскрипт прикріплюється до сторінки файлом `<call>-transcript.md`.

Що для цього потрібно:

- токен Notion у **Settings > Keys** (внутрішня інтеграція з
  [notion.so/my-integrations](https://www.notion.so/my-integrations)) з доступом до бази
  Meetings;
- конфіг проєкту з `meetings_db` і `project_page_id` (розділ 4, крок 7).

У Claude і Notion іде лише текст транскрипту; звук не покидає Мак. Після запису зʼявляється
повідомлення з кнопкою **Open in Notion**. Якщо скіл уже написав сторінку цієї зустрічі,
застосунок додає свій розділ до неї, а не створює другу.

### 14.3 Застосунок і скіл на одному дзвінку

Обидва можна запустити на одному дзвінку: для чесного порівняння або як запасний варіант.
Застосунок пише своїм рекордером у своїй теці і називає файли `<call>.app.*`
(`2026-10-22-1500-team-daily.app.md`), тож транскрипт, файли керування і стану в них не
спільні. Обидва запускають Whisper, тож процесор і памʼять навантажуються приблизно вдвічі.
Порівняти після дзвінка:

```bash
python -m livetips_m0.report <app folder>/runs/<call>.app --calls-root <project folder>/live
python -m livetips_m0.judge --config <cfg.json> --md <project folder>/live/<call>.md \
  --run <app folder>/runs/<call>.app --out <app folder>/runs/judge-<call>
```

`report` показує кількість підказок, затримку і вартість кожного боку; `judge` це сліпий суддя,
який оцінює кожну підказку обох боків від 1 до 5, не знаючи, хто її написав.

### 14.4 Гарячі клавіші

- **Control-Option-H**: ДОПОМОЖИ, навіть коли фокус у застосунку зустрічі.
- **Control-Option-P**: пауза або продовження підказок.

Ці дві дії є і в меню в рядку меню під час дзвінка, з клавішами поруч. Кнопка ДОПОМОЖИ
показує свою комбінацію, кнопка паузи показує її в підказці, а **Settings > General >
Shortcuts** перелічує обидві.
