# 17. Live tips: асистент на дзвінку

[English](../en/17-live-tips.md) · [До змісту](README.md)

Live tips - це блок, який слухає дзвінок разом з ПМом і підказує в чаті Cowork. Аудіо
розпізнається локально на Маку, назовні нічого не йде. Скіл читає транскрипт рядок за рядком
і звіряє його з контекстом проєкту. Мовчить, поки не спрацює тригер: прохання, схоже на нову вимогу,
обіцянка дати чи оцінки, суперечність ухваленому рішенню, неточна або неповна відповідь ПМа,
розмова клієнтів між собою іншою мовою. Після дзвінка в Meetings DB з'являється сторінка з
транскриптом і підсумком.

Документ розрахований на три ситуації:

1. відтворити все з нуля на новому Маку;
2. пригадати, як воно працює, коли щось зламалось;
3. колега хоче поставити те саме в себе.

## 1. Як це влаштовано

```
                    Мак (локально)                                    Cowork (хмара)
┌──────────────────────────────────────────────────────────┐    ┌──────────────────────────┐
│ LaunchAgent  ──стежить за──>  control/                   │    │ скіл live-tips           │
│     │ з'явився start.json                                │<───│  пише control/start.json │
│     v                                                    │    │                          │
│ Terminal: bin/run.command                                │    │  long-poll:              │
│     v                                                    │    │  bin/read_delta.py       │
│ src/transcriber.py                                       │    │  -> нові рядки           │
│   ├─ bin/audiocap --source mic     (мікрофон)            │    │  -> тригери -> підказка  │
│   ├─ bin/audiocap --source system  (системний звук)      │    │     в чаті               │
│   ├─ VAD ріже на фрази                                   │    │                          │
│   ├─ Whisper large-v3-turbo (MLX) на кожну фразу         │    │  "стоп" -> control/stop  │
│   ├─ прибирає відлуння і галюцинації                     │    │                          │
│   └─> <проєкт>/live/2026-10-10-2348-<назва>.md ──────────┼───>│  підсумок + сторінка     │
│       state/status.json  (стан для скіла) ───────────────┼───>│  в Notion Meetings DB    │
└──────────────────────────────────────────────────────────┘    └──────────────────────────┘
```

Чому саме так:

- **Локальний Whisper.** Розмови з клієнтом не йдуть у сторонній сервіс транскрипції. Модель
  `mlx-community/whisper-large-v3-turbo` працює на Apple Silicon через MLX. Мережа потрібна
  лише раз, щоб скачати модель (~1.6 ГБ).
- **Два канали замість одного.** `audiocap` (Swift) окремо пише мікрофон і системний звук.
  Системний звук знімається через Core Audio process tap (macOS 14.2+), тому BlackHole не
  потрібен, а зміна навушників чи динаміків не ламає запис. Завдяки двом каналам
  транскрипт знає, хто говорить: `Я` = мікрофон, `Співрозмовник` = усі інші.
- **Фіксована мова мікрофона.** Мова ПМа на дзвінку відома наперед (`me_lang`), а для
  співрозмовників Whisper вибирає мову лише з дозволеного набору (`langs`, напр. `en+es`).
  Це помітно краще за повний автодетект: українська не перетворюється на російську,
  іспанські репліки не перекладаються англійською.
- **Terminal, а не фоновий процес.** macOS видає дозволи на мікрофон і запис системного звуку
  застосунку. Запис стартує у вікні Terminal, тож дозволи належать Terminal і даються один раз.
  LaunchAgent лише відкриває це вікно, коли скіл кладе `control/start.json`.
- **Файл як інтерфейс.** Скіл працює з Маком через shell у підключеній папці Cowork
  (`device_bash`) і нічого не знає про аудіо. Між скілом і записом стоять лише файли:
  `control/start.json`, `control/stop`, `state/status.json` і сам транскрипт.

## 2. Компоненти

Код лежить у [`tools/live-transcriber/`](../../tools/live-transcriber/), скіл у
[`plugin/skills/live-tips/`](../../plugin/skills/live-tips/).

| Файл | Роль |
|---|---|
| `install.sh` | Одноразове встановлення: збірка `audiocap`, venv з `mlx-whisper`, модель, LaunchAgent, тест дозволів. Можна запускати повторно |
| `config.json` | Модель, мітки каналів, мови за замовчуванням, `launchd_label`. Поля зі `start.json` мають пріоритет |
| `src/audiocap.swift` | Захоплення аудіо: `--source mic` або `--source system`, на виході float32 16 кГц mono у stdout. Сам перепідключається при зміні пристрою |
| `src/Info.plist` | Вшивається в бінарник, містить тексти запитів дозволів |
| `src/transcriber.py` | Серце: два потоки захоплення, VAD (webrtcvad, без нього енергетичний), Whisper, фільтр галюцинацій, прибирання відлуння, запис рядків, `status.json` |
| `bin/run.command` | Запускає `transcriber.py --from-control` у вікні Terminal "Live transcriber" |
| `bin/on-control.sh` | Викликається LaunchAgent при зміні `control/`. Якщо є `start.json` і запис не йде, відкриває Terminal |
| `bin/read_delta.py` | Long-poll для скіла: чекає до `--wait` с на нові рядки, віддає лише нові повні рядки, `@@OFFSET` і `@@STATUS` |
| `launchd/live-transcriber.plist.template` | Шаблон LaunchAgent (`WatchPaths` на `control/`) |
| `plugin/skills/live-tips/SKILL.md` | Скіл: старт, Live Brief, цикл підказок, стоп, підсумок, сторінка в Meetings DB |
| `plugin/skills/live-tips/settings.yaml` | Усе особисте: мітки, шляхи, мови, правила підказок, часова зона |

Runtime-папки (не в git): `.venv/`, `bin/audiocap`, `logs/`, `state/`, `control/`.

### Файли керування і стану

| Шлях | Хто пише | Що означає |
|---|---|---|
| `control/start.json` | скіл або людина | Запит на старт: `project_dir`, `title`, `slug`, `me_lang`, `langs`, `me_label`, `them_label`, `prompt`. При старті перейменовується на `control/active.json` |
| `control/stop` | скіл або людина (`touch`) | Запит на зупинку. Вміст не важливий |
| `state/status.json` | transcriber | `state` (`loading_model` → `recording` → `stopping` → `stopped`, або `error`), `file`, `started_at` (зі зсувом), `timezone`, `lines`, `queue`, `mic`, `system_audio`, `errors` |
| `state/pid`, `state/launching` | transcriber / on-control.sh | Захист від подвійного старту |
| `logs/transcriber.log`, `logs/launcher.log`, `logs/install.log`, `logs/audiocap-*.log` | усі | Перше місце, куди дивитись при збої |

### Формат транскрипту

`<папка проєкту>/live/<YYYY-MM-DD-HHMM>-<назва>.md`:

```
# Live transcript: Status sync

- Проєкт: acme-portal
- Початок: 2026-10-10 23:48:02
- Мови: Я = en, дозволені = en+es
...
[23:48:11] Я (en): Can you hear me?
[23:48:15] Співрозмовник (es): Sí, perfecto.

--- кінець запису 00:31:40 ---
```

Поруч скіл кладе `<назва>.brief.md` (Live Brief) і `<назва>.state.json` (зсув читання,
видані підказки, пари питання-відповідь, action items).

## 3. Вимоги

- Мак на Apple Silicon (M1 і новіші), macOS 14.2 або новіша.
- Xcode Command Line Tools (`xcode-select --install`; якщо їх немає, `install.sh` сам
  запропонує).
- Python 3.10+ (`brew install python@3.12`).
- ~2.5 ГБ вільного місця (модель + venv).
- Claude desktop (Cowork) з підключеною папкою, у якій лежать інструмент і папки проєктів
  (у автора `~/work`).
- Плагін `pm-control-tower` з конфігом проєкту в `projects/<slug>.md`. Скіл бере звідти
  команду, мітинги, `Local Paths` і Notion ID (`meetings_db`, `project_page_id`,
  `workspace_page_id`).
- Конектор Notion у Cowork (для Live Brief і сторінки в Meetings DB). Без нього підказки
  працюють, але без контексту з Notion і без сторінки після дзвінка.

## 4. Встановлення з нуля

1. **Покласти інструмент на Мак.** Скопіюй `tools/live-transcriber/` з цього репозиторію в
   `~/work/Tools/live-transcriber` (шлях можна інший, тоді виправ його в `settings.yaml`):
   ```
   mkdir -p ~/work/Tools
   cp -R "<клон репозиторію>/tools/live-transcriber" ~/work/Tools/
   ```
2. **Назва LaunchAgent.** За замовчуванням `com.pm-control-tower.live-transcriber`. Якщо
   хочеш свій префікс, зміни `launchd_label` у `config.json` до встановлення.
3. **Встановити:**
   ```
   bash ~/work/Tools/live-transcriber/install.sh
   ```
   Займає 5-10 хвилин, найдовше качається модель. Під час тесту дозволів macOS спитає
   доступ для Terminal до мікрофона і до запису системного звуку: обидва треба дозволити.
   Коли скрипт попросить, увімкни будь-який звук (YouTube) на 5 с.
4. **Перевірити `logs/install.log`.** Наприкінці має бути `=== install OK`, а в рядках
   `mic: ... peak` і `sys: ... peak` обидва піки більші за нуль. `sys: 0.0 s, peak 0.0000`
   означає одне з двох: під час тесту нічого не грало (найчастіше) або немає дозволу.
   Перевірка: увімкни YouTube і запусти
   `~/work/Tools/live-transcriber/bin/audiocap --source system --seconds 5 | wc -c`.
   Число більше нуля (~330 000 за 5 с) означає, що все гаразд. Нуль: див. розділ 10.
5. **Скіл.** Плагін `pm-control-tower` (від 1.6.0) уже містить `live-tips`. Заповни
   `plugin/skills/live-tips/settings.yaml`: `paths.work_root`, `paths.tool_root`, мітки,
   мови, `user.timezone`. При налаштуванні плагіна `~~home-folder` підставиться сам.
6. **Cowork.** Підключи в Claude desktop папку `work_root` (кнопка "Add folder"). Скіл
   звертається до неї як до `$HOME/mnt/<ім'я папки>`.
7. **Конфіг проєкту.** У `projects/<slug>.md` мають бути `Local Paths` (з них береться папка
   проєкту, куди писати `live/`), `notion.meetings_db`, `notion.project_page_id`,
   `notion.workspace_page_id`, а для клієнтських дзвінків `client_language`.
8. **Пробний запис без скіла** (перевіряє все, крім Cowork):
   ```
   cd ~/work/Tools/live-transcriber
   .venv/bin/python src/transcriber.py --project-dir ~/work/Test --title "Тест" --me-lang uk --langs uk+en
   ```
   Поговори хвилину, зупини через Ctrl+C, відкрий `~/work/Test/live/…-тест.md`.

## 5. Як провести дзвінок

### 5.0 Перед дзвінком: модель і підготовка

**Яку модель обрати для сесії.** Кожна секунда роздумів моделі додається до затримки
підказки, тому вибір залежить від дзвінка:

| Дзвінок | Модель | Чому |
|---|---|---|
| Звичайні синки, стендапи, статуси | Sonnet 5.5, low або medium effort | Встигає за розмовою і досить уважна для перевірки відповідей |
| Інтерв'ю з клієнтом, ескалація, steering, важкі переговори | Opus 5.5 | Глибше бачить суперечності й недомовки; затримка 10-30 с на таких дзвінках прийнятна |
| Haiku | не рекомендовано | Занадто поверхово для перевірки відповідей і нюансів кількох мов |

**Підготовка в тій самій сесії.** Найкраще працює так: відкрити сесію в проєкті Cowork,
спершу зробити prep, а безпосередньо перед дзвінком написати `live tips`.

1. Prep: `client-meeting-prep` або `daily-team-prep`, чи вільний запит на кшталт
   "підготуй мене до інтерв'ю з клієнтом про звіти по транзакціях, візьми в першу чергу
   сторінки Notion <посилання> і папку <шлях>". Деталі мітингу, цілі, питання, сторінки й
   папки, які варто взяти в контекст першими, пишеш тут.
2. Перед дзвінком: `live tips <проєкт>`. Скіл бачить усе, що підготовлено раніше в сесії,
   і будує Live Brief довкола цього: цілі й питання з prep стають чеклістом, вказані
   сторінки й папка стають основою карти тем. Це пріоритет, а не обмеження: решта
   контексту проєкту (рішення, ризики, трекер, минулі мітинги) теж підтягується і
   використовується, коли розмова йде вбік.

**Інтерв'ю з клієнтом.** Якщо з prep чи з твоїх слів зрозуміло, що це інтерв'ю на тему,
скіл перемикається в режим інтерв'ю: чекліст = твої заплановані питання. Він відстежує, які
питання поставлені і наскільки повно на них відповіли. Підказує, де відповідь розмита і
варто уточнити (готовим питанням англійською), де відповідь суперечить відомому, де
з'явилась нова тема для уточнення, які питання ще не поставлені ближче до кінця. У
підсумку окремий блок "Відповіді на питання інтерв'ю": питання → відповідь одним рядком →
статус.

### 5.1 Під час дзвінка

1. За хвилину до дзвінка напиши в Cowork: **`live tips <проєкт>`** (або "лайв підказки",
   "я на дзвінку", "дзвінок почався"). Якщо проєкт не названий, скіл спитає. Мову і
   тривалість можна дописати: "live tips acme, внутрішній, українською, 30 хв".
2. Скіл перевіряє, що інструмент встановлений і що нічого вже не пишеться, кладе
   `control/start.json` і чекає `recording` (5-20 с на завантаження моделі). Вікно Terminal
   "Live transcriber" відкривається само: запускати його не треба. Запис живе саме в ньому,
   бо дозволи macOS на мікрофон і системний звук видані Terminal. Вікно можна згорнути
   (Cmd+M) або сховати за іншими, але не закривати. Якщо все ж закрити, запис акуратно
   зупиниться, а вже записаний транскрипт залишиться.
3. У чаті з'являється `Запис іде: <файл>. Мови: я en, дозволені en+es.`, а за хвилину
   чекліст мітингу з Live Brief (відкриті теми, рішення, ризики, обіцянки з минулих
   мітингів, тікети) і `Мовчу, поки нема що сказати.`
4. Далі скіл мовчить, поки не спрацює тригер.

| Рівень | Коли |
|---|---|
| 🔴 одразу | Прохання, схоже на нову вимогу; ПМ називає дату чи оцінку; суперечність ухваленому рішенню; сигнал незадоволення; ПМ сказав факт, що суперечить трекеру чи рішенням |
| 🟠 не частіше ніж раз на `rate_seconds` | ПМ відповів не на те питання або не на все; розмита відповідь там, де чекали дату чи власника; співрозмовники перейшли на іншу мову (коротка суть); згадана тема чи тікет з брифу; питання без відповіді ~2 хв; 2/3 часу і непокриті пункти; 5 хв до кінця і неотримані рішення |
| тихо | Action items, нові вимоги, зобов'язання: потрапляють у підсумок |

### Як виглядає підказка

Розраховано на маленьке вікно Cowork вгорі по центру екрана, під камерою, щоб погляд не
бігав. Тому кожна підказка має 2-5 коротких рядків (до ~45 символів), без таблиць,
заголовків і посилань.

1. **Суть**, жирним: емодзі і що відбувається, українською, до 7 слів. Завжди першим
   рядком, щоб за секунду зрозуміти, про що мова.
2. **Фраза**, в лапках, мовою дзвінка. Це готова мова, яку можна прочитати вголос як є,
   а не тези. 1-2 речення. Англійською прості речення до 12 слів, побутова лексика, Present
   або Future Simple, активний стан, без ідіом і довгих підрядних.
3. **Факти** (лише для статусу і розмови співрозмовників між собою): до 3 рядків до 8 слів.
4. **Джерело** (лише для 🔴 суперечностей і неточностей): один короткий рядок курсивом.

**Без абревіатур:** "нова вимога", а не CR, "термін", а не ETA. Ключів тікетів теж немає,
замість них назва теми. Імена людей і назви продуктів лишаються як є.

Приклади на англійському дзвінку:

> **🔴 Нова вимога. Не погоджуй зараз.**
> "Good idea. I will write it down. We will check it and come back to you."

> **🔴 Неточно: реліз 15.10, не 10.10**
> "Sorry, a small correction. The release date is October 15."
> _рішення від 30.09_

> **🟠 Питали про термін, не про обсяг**
> "About the date: I will confirm it with the team by Friday."

> **🟠 Між собою іспанською**
> Сумніваються, чи встигнуть протестувати до релізу.

На внутрішньому українському дзвінку і суть, і фраза українською.

Підказка з 🔒 спирається на внутрішнє джерело: її не можна повторювати клієнту вголос.
Оцінок у годинах скіл ніколи не пропонує: "оцінку дає виконавець, зафіксуй і повернись".

**Питання під час дзвінка.** Пиши в чат будь-що ("що ми обіцяли по X?", "який статус
ACME-123?"). Скіл відповідає коротко з брифу і транскрипту, потім продовжує слухати з
того самого місця. Якщо цикл зупинився, напиши "продовжуй".

## 6. Як завершити мітинг

Три рівноцінні способи. У кожному з них транскрипт закривається рядком
`--- кінець запису HH:MM:SS ---`.

1. **У чаті (звичайний шлях):** напиши `стоп`, `все`, `кінець` або `кінець дзвінка`. Скіл
   створює `control/stop`, чекає до 60 с, поки дорозпізнаються останні фрази, і читає
   останні рядки.
2. **У вікні Terminal** "Live transcriber" (воно відкрилось само на старті): Ctrl+C або
   закрити вікно. Це запасний шлях, якщо чат недоступний. Скіл побачить `stopped` на
   наступному опитуванні.
3. **Автоматично:** якщо після щонайменше 20 рядків `idle_stop_minutes` хвилин немає нових
   реплік, скіл один раз питає "Дзвінок закінчився? Зупиняю запис через 2 хв" і зупиняє.
   Жорстка межа: запланована тривалість + 20 хв або `hard_cap_minutes`.

Важливо: **закриття Zoom/Meet запис не зупиняє.** Інструмент далі слухає системний звук
(музику, відео). Треба один із трьох способів вище.

Вручну без скіла: `touch ~/work/Tools/live-transcriber/control/stop`.

## 7. Що відбувається після дзвінка

### 7.1 Підсумок у чаті (українською)

Action items (хто / що / коли), нові вимоги, наші зобов'язання, відкриті питання,
"Відповіді, до яких варто повернутись" (питання → що не так → як закрити), непокриті пункти
чекліста, шлях до транскрипту, посилання на сторінку в Notion. Далі скіл лише пропонує
наступні кроки (звіт, change-request, risk-register) і нічого не запускає без команди.

### 7.2 Сторінка в Meetings DB (автоматично)

Скіл створює одну сторінку в `notion.meetings_db` проєкту:

| Що | Значення |
|---|---|
| Назва | `<згенерована назва> @<дата-час початку>`. Назву скіл складає з того, про що реально говорили (2-6 слів, мовою дзвінка). Дата-час у назві є Notion date mention, тобто клікабельною датою, як у нативних AI Meeting Notes |
| `Date` | Дата і час початку мітингу (`started_at` зі `status.json`, з часовим зсувом Мака) |
| `Project` | Сторінка проєкту (`notion.project_page_id`) |
| `Workspace` | Воркспейс, до якого належить проєкт: береться з relation `Workspace` на сторінці проєкту (запасний варіант `notion.workspace_page_id`). Приклад: проєкт належить воркспейсу компанії, у якій ти працюєш |
| `Meeting type` | Лише якщо тип мітингу точно збігається з наявною опцією; нові опції скіл не створює |
| `Summary` | 1-2 речення |
| Тіло | Блок AI Meeting Notes з транскриптом, під ним розділ "Підсумок" (action items як to-do, нові вимоги, відкриті питання) |

**Обмеження Notion API (перевірено 2026-10-11).** Секції `Transcript` і `Summary` блоку AI
Meeting Notes через API не записуються: специфікація Notion прямо каже, що запис у
`<transcript>` завершується помилкою. Генерацію саммарі Notion AI через API теж не
запустити. Тому:

- транскрипт кладеться в секцію **Notes** блоку AI Meeting Notes (по рядку на абзац);
- саммарі пише сам скіл (поле `Summary` і розділ "Підсумок");
- якщо хочеш саммарі саме від Notion AI, натисни Notion AI у блоці вручну.

Технічна деталь, щоб не наступити вдруге. `notion-create-pages` зберігає
`<mention-date …/>` у назві як звичайний текст. Тому скіл спочатку створює сторінку з
простою назвою, а потім ставить назву з датою через `notion-update-page`
(`update_properties`), який mention розпізнає. Після цього скіл перечитує сторінку і
перевіряє назву, поля і кількість рядків.

Якщо мітинг записувався через Notion AI Meeting Notes (fallback, розділ 8), друга сторінка
не створюється: справжній транскрипт уже є в Notion.

## 8. Fallback: Notion AI Meeting Notes

Якщо Мак офлайн або live-transcriber не стартує, увімкни запис у Notion AI Meeting Notes
і скинь скілу посилання на сторінку мітингу. Скіл читатиме транскрипт звідти. Підказки
будуть менш точні: у Notion немає міток спікерів, а українську мову він подекуди
перетворює на кострубату англійську. Для цього режиму є окремий скіл `notion-live-tips`
(у пакет не входить).

## 9. Налаштування `settings.yaml`

| Ключ | Що задає |
|---|---|
| `user.me_label`, `user.them_label` | Мітки каналів у транскрипті |
| `user.tips_language` | Мова підказок і підсумку |
| `user.timezone` | Запасна IANA-зона. Зазвичай не потрібна: live-transcriber сам пише в `status.json` зону і зсув годинника Мака (Notion приймає `Europe/Kiev`) |
| `paths.work_root` | Папка Мака, підключена до Cowork |
| `paths.tool_root` | Де лежить live-transcriber |
| `languages.internal` | Мова мікрофона і дозволені мови для внутрішніх дзвінків |
| `languages.client` | Те саме для клієнтських; `from_project` = `client_language` з конфігу |
| `languages.per_project.<slug>.<internal\|client>` | Перевизначення для конкретного проєкту |
| `tips.rate_seconds` | Мінімальний інтервал між некритичними підказками |
| `tips.answer_check` | Перевіряти відповіді самого ПМа |
| `tips.side_talk_summary` | Підсумовувати розмову співрозмовників між собою іншою мовою |
| `tips.idle_stop_minutes`, `tips.hard_cap_minutes` | Автостоп |
| `model_hint` | Яку модель Claude брати для сесії (див. розділ 5.0) |

**Де лежить `settings.yaml`.** Це файл усередині скіла `live-tips` у твоєму акаунті Claude,
а не окремий файл на Маку. Щоб його змінити, правиш файл у папці скіла і завантажуєш скіл
заново (zip з папкою `live-tips/`, де лежать `SKILL.md` і `settings.yaml`) у налаштуваннях
Claude, розділ Skills. У репозиторії шаблон лежить у `plugin/skills/live-tips/settings.yaml`.

Тонкі параметри розпізнавання (`vad_mode`, `end_silence`, `max_segment`, вікно відлуння)
лежать у `DEFAULTS` в `src/transcriber.py` і за потреби перевизначаються в `config.json`.

## 10. Траблшутінг

| Симптом | Причина і що робити |
|---|---|
| `start.json` лежить, а запис за 60 с не стартує | LaunchAgent не завантажений або інсталяцію не запускали. `launchctl list \| grep live-transcriber`; якщо порожньо, запусти `install.sh`. Скіл у такому разі перейменовує файл на `start.json.pending`, щоб запис не стартував несподівано пізніше |
| `system=silent`, у транскрипті лише "Я" | Немає дозволу на запис системного звуку. System Settings → Privacy & Security → Screen & System Audio Recording → System Audio Recording Only → Terminal. Перевірка: увімкни звук і запусти `bin/audiocap --source system --seconds 5 \| wc -c`, має бути більше нуля |
| `mic=silent` | Дозвіл на мікрофон для Terminal (Privacy & Security → Microphone) або вибрано не той вхідний пристрій |
| У `audiocap-mic.log` багато `mic restart: engine configuration change` | Норма при підключенні або відключенні навушників: мікрофон перепідключається сам |
| `no IO from tap-only aggregate, retrying with output device as clock` | Норма: запасний режим тактування системного тапу |
| `queue` росте, підказки запізнюються | Мак перевантажений (відео, збірка). Транскрипція наздожене; скіл попереджає один раз |
| Українська розпізнається як російська, імена спотворені | Перевір `me_lang`; додай імена в `prompt` (скіл збирає ~200 символів імен і термінів з конфігу) |
| Рядки "Дякую за перегляд", "Субтитри…" | Галюцинації Whisper на тиші; основні фрази відфільтровуються (`HALLUCINATIONS` у `transcriber.py`), нові можна дописати туди |
| Після перевстановлення з іншим `launchd_label` Terminal відкривається двічі | Працюють два LaunchAgent. Вивантаж старий: `launchctl bootout gui/$(id -u)/<старий label>` і видали його plist з `~/Library/LaunchAgents` |
| У назві сторінки Notion видно `<mention-date …>` текстом | Назву поставили через create, а не через update. Див. розділ 7.2 |

## 11. Приватність і етикет

- Аудіо не зберігається: розпізнані фрази одразу дописуються в `.md`, аудіобуфери живуть
  лише в пам'яті.
- Транскрипти лежать у папці проєкту (`<проєкт>/live/`). Не додавай їх у публічні
  репозиторії.
- Сторінка в Meetings DB внутрішня. Скіл ніколи нічого не надсилає клієнту.
- Попереджай учасників, що ведеш транскрипт, як і з будь-яким записувачем. Вимоги до
  згоди різняться залежно від країни і договору з клієнтом.
