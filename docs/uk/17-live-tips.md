# 17. Live tips: асистент на дзвінку

[English](../en/17-live-tips.md) · [До змісту](README.md)

Live tips - це блок, який слухає дзвінок разом з ПМом і підказує в чаті Cowork. Аудіо
розпізнається локально на Маку, назовні нічого не йде. Скіл читає транскрипт рядок за рядком
і звіряє його з контекстом проєкту. На старті показує твій спіч чи статус, далі підказує, коли це допомагає: прохання, схоже на
нову вимогу, обіцянка дати чи оцінки, суперечність ухваленому рішенню, неточна або неповна
відповідь, перехід співрозмовників на іншу мову, момент, де можна додати факт чи поставити
питання. Миттєві картки з підготовки з'являються за 1-2 с після фрази-тригера. Покриває і
співбесіди (спостерігач, кандидат, інтерв'юер). Після дзвінка підсумок іде в Meetings DB:
в уже наявну сторінку мітингу (наприклад, створену Notion AI Meeting Notes) або в нову, якщо
такої немає.

Документ розрахований на три ситуації:

1. відтворити все з нуля на новому Маку;
2. пригадати, як воно працює, коли щось зламалось;
3. колега хоче поставити те саме в себе.

## 1. Як це влаштовано

```
                    Мак (локально)                                    Cowork (хмара)
┌──────────────────────────────────────────────────────────┐    ┌──────────────────────────┐
│ LaunchAgent  ──стежить за──>  control/                   │    │ скіл live-tips           │
│     │ з'явився start.json                                │<───│  пише control/start.json │
│     v                                                    │    │                          │
│ Terminal: bin/run.command                                │    │  long-poll:              │
│     v                                                    │    │  bin/read_delta.py       │
│ src/transcriber.py                                       │    │  -> нові рядки           │
│   ├─ bin/audiocap --source mic     (мікрофон)            │    │  -> тригери -> підказка  │
│   ├─ bin/audiocap --source system  (системний звук)      │    │     в чаті               │
│   ├─ VAD ріже на фрази                                   │    │                          │
│   ├─ Whisper large-v3-turbo (MLX) на кожну фразу         │    │  "стоп" -> control/stop  │
│   ├─ прибирає відлуння і галюцинації                     │    │                          │
│   └─> <проєкт>/live/2026-10-10-2348-<назва>.md ──────────┼───>│  підсумок + сторінка     │
│       state/status.json  (стан для скіла) ───────────────┼───>│  в Notion Meetings DB    │
└──────────────────────────────────────────────────────────┘    └──────────────────────────┘
```

Чому саме так:

- **Локальний Whisper.** Розмови з клієнтом не йдуть у сторонній сервіс транскрипції. Модель
  `mlx-community/whisper-large-v3-turbo` працює на Apple Silicon через MLX. Мережа потрібна
  лише раз, щоб скачати модель (~1.6 ГБ).
- **Два канали замість одного.** `audiocap` (Swift) окремо пише мікрофон і системний звук.
  Системний звук знімається через Core Audio process tap (macOS 14.2+), тому BlackHole не
  потрібен, а зміна навушників чи динаміків не ламає запис. Завдяки двом каналам
  транскрипт знає, хто говорить: `Я` = мікрофон, `Співрозмовник` = усі інші.
- **Фіксована мова мікрофона.** Мова ПМа на дзвінку відома наперед (`me_lang`), а для
  співрозмовників Whisper вибирає мову лише з дозволеного набору (`langs`, напр. `en+es`).
  Це помітно краще за повний автодетект: українська не перетворюється на російську,
  іспанські репліки не перекладаються англійською.
- **Terminal, а не фоновий процес.** macOS видає дозволи на мікрофон і запис системного звуку
  застосунку. Запис стартує у вікні Terminal, тож дозволи належать Terminal і даються один раз.
  LaunchAgent лише відкриває це вікно, коли скіл кладе `control/start.json`.
- **Файл як інтерфейс.** Скіл працює з Маком через shell у підключеній папці Cowork
  (`device_bash`) і нічого не знає про аудіо. Між скілом і записом стоять лише файли:
  `control/start.json`, `control/stop`, `state/status.json` і сам транскрипт.

## 2. Компоненти

Код лежить у [`tools/live-transcriber/`](../../tools/live-transcriber/), скіл у
[`plugin/skills/live-tips/`](../../plugin/skills/live-tips/).

| Файл | Роль |
|---|---|
| `install.sh` | Одноразове встановлення: збірка `audiocap`, venv з `mlx-whisper`, модель, LaunchAgent, тест дозволів. Можна запускати повторно |
| `config.json` | Модель, мітки каналів, мови за замовчуванням, `launchd_label`. Поля зі `start.json` мають пріоритет |
| `src/audiocap.swift` | Захоплення аудіо: `--source mic` або `--source system`, на виході float32 16 кГц mono у stdout. Сам перепідключається при зміні пристрою |
| `src/Info.plist` | Вшивається в бінарник, містить тексти запитів дозволів |
| `src/transcriber.py` | Серце: два потоки захоплення, VAD (webrtcvad, без нього енергетичний), Whisper, фільтр галюцинацій, прибирання відлуння, запис рядків, `status.json` |
| `bin/run.command` | Запускає `transcriber.py --from-control` у вікні Terminal "Live transcriber" |
| `bin/on-control.sh` | Викликається LaunchAgent при зміні `control/`. Якщо є `start.json` і запис не йде, відкриває Terminal |
| `bin/read_delta.py` | Один виклик на ітерацію скіла: дописує нові підказки у вікно (`--emit-stdin`), чекає до `--wait` с на нові рядки транскрипту чи питання з вікна, віддає лише нове, `@@ASK`, `@@OFFSET`, `@@INBOX_OFFSET`, `@@STATUS` |
| `src/prompter.swift`, `src/prompter.html` | Вікно-суфлер: завжди поверх інших вікон, рухається, згортається, закривається, просить macOS не потрапляти в демонстрацію екрана; показує `*.tips.jsonl`, пише питання в `*.inbox.jsonl`. Збирається в `bin/prompter` |
| `launchd/live-transcriber.plist.template` | Шаблон LaunchAgent (`WatchPaths` на `control/`) |
| `plugin/skills/live-tips/SKILL.md` | Скіл: старт, Live Brief, цикл підказок, стоп, підсумок, сторінка в Meetings DB |
| `plugin/skills/live-tips/settings.yaml` | Усе особисте: мітки, шляхи, мови, правила підказок, часова зона |

Runtime-папки (не в git): `.venv/`, `bin/audiocap`, `logs/`, `state/`, `control/`.

### Файли керування і стану

| Шлях | Хто пише | Що означає |
|---|---|---|
| `control/start.json` | скіл або людина | Запит на старт: `project_dir`, `title`, `slug`, `me_lang`, `langs`, `me_label`, `them_label`, `prompt`. При старті перейменовується на `control/active.json` |
| `control/stop` | скіл або людина (`touch`) | Запит на зупинку. Вміст не важливий |
| `state/status.json` | transcriber | `state` (`loading_model` → `recording` → `stopping` → `stopped`, або `error`), `file`, `started_at` (зі зсувом), `timezone`, `lines`, `queue`, `mic`, `system_audio`, `errors` |
| `state/pid`, `state/launching` | transcriber / on-control.sh | Захист від подвійного старту |
| `logs/transcriber.log`, `logs/launcher.log`, `logs/install.log`, `logs/audiocap-*.log` | усі | Перше місце, куди дивитись при збої |

### Формат транскрипту

`<папка проєкту>/live/<YYYY-MM-DD-HHMM>-<назва>.md`:

```
# Live transcript: Status sync

- Проєкт: acme-portal
- Початок: 2026-10-10 23:48:02
- Мови: Я = en, дозволені = en+es
- Мікрофон: системний вхід за замовчуванням (навушники або Мак)
...
[23:48:11] Я (en): Can you hear me?
[23:48:15] Співрозмовник (es): Sí, perfecto.

--- кінець запису 00:31:40 ---
```

Поруч скіл кладе `<назва>.brief.md` (Live Brief) і `<назва>.state.json` (зсув читання,
видані підказки, пари питання-відповідь, action items).

## 3. Вимоги

- Мак на Apple Silicon (M1 і новіші), macOS 14.2 або новіша.
- Xcode Command Line Tools (`xcode-select --install`; якщо їх немає, `install.sh` сам
  запропонує).
- Python 3.10+ (`brew install python@3.12`).
- ~2.5 ГБ вільного місця (модель + venv).
- Claude desktop (Cowork) з підключеною папкою, у якій лежать інструмент і папки проєктів
  (у автора `~/work`).
- Плагін `pm-control-tower` з конфігом проєкту в `projects/<slug>.md`. Скіл бере звідти
  команду, мітинги, `Local Paths` і Notion ID (`meetings_db`, `project_page_id`,
  `workspace_page_id`).
- Конектор Notion у Cowork (для Live Brief і сторінки в Meetings DB). Без нього підказки
  працюють, але без контексту з Notion і без сторінки після дзвінка.

## 4. Встановлення з нуля

1. **Покласти інструмент на Мак.** Скопіюй `tools/live-transcriber/` з цього репозиторію в
   `~/work/Tools/live-transcriber` (шлях можна інший, тоді виправ його в `settings.yaml`):
   ```
   mkdir -p ~/work/Tools
   cp -R "<клон репозиторію>/tools/live-transcriber" ~/work/Tools/
   ```
2. **Назва LaunchAgent.** За замовчуванням `com.pm-control-tower.live-transcriber`. Якщо
   хочеш свій префікс, зміни `launchd_label` у `config.json` до встановлення.
3. **Встановити:**
   ```
   bash ~/work/Tools/live-transcriber/install.sh
   ```
   Займає 5-10 хвилин, найдовше качається модель. Під час тесту дозволів macOS спитає
   доступ для Terminal до мікрофона і до запису системного звуку: обидва треба дозволити.
   Коли скрипт попросить, увімкни будь-який звук (YouTube) на 5 с.
4. **Перевірити `logs/install.log`.** Наприкінці має бути `=== install OK`, а в рядках
   `mic: ... peak` і `sys: ... peak` обидва піки більші за нуль. `sys: 0.0 s, peak 0.0000`
   означає одне з двох: під час тесту нічого не грало (найчастіше) або немає дозволу.
   Перевірка: увімкни YouTube і запусти
   `~/work/Tools/live-transcriber/bin/audiocap --source system --seconds 5 | wc -c`.
   Число більше нуля (~330 000 за 5 с) означає, що все гаразд. Нуль: див. розділ 10.
5. **Скіл.** Плагін `pm-control-tower` (від 1.6.0) уже містить `live-tips`. Заповни
   `plugin/skills/live-tips/settings.yaml`: `paths.work_root`, `paths.tool_root`, мітки,
   мови, `user.timezone`. При налаштуванні плагіна `~~home-folder` підставиться сам.
5a. **Плагін-запобіжник (рекомендовано).** Встанови `tools/live-tips-keepalive` як плагін
   Cowork (запакуй теку в `live-tips-keepalive.plugin`). Поки йде запис, його Stop-хук не
   дає Claude завершити хід, тож цикл підказок не замовкне сам. Якщо щось не так, хук нічого
   не блокує: немає позначки, позначка протухла (2,5 год) або 400 блокувань. Скіл ставить
   позначку на старті й прибирає після підсумку.
6. **Cowork.** Підключи в Claude desktop папку `work_root` (кнопка "Add folder"). Скіл
   звертається до неї як до `$HOME/mnt/<ім'я папки>`.
7. **Конфіг проєкту.** У `projects/<slug>.md` мають бути `Local Paths` (з них береться папка
   проєкту, куди писати `live/`), `notion.meetings_db`, `notion.project_page_id`,
   `notion.workspace_page_id`, а для клієнтських дзвінків `client_language`.
8. **Пробний запис без скіла** (перевіряє все, крім Cowork):
   ```
   cd ~/work/Tools/live-transcriber
   .venv/bin/python src/transcriber.py --project-dir ~/work/Test --title "Тест" --me-lang uk --langs uk+en
   ```
   Поговори хвилину, зупини через Ctrl+C, відкрий `~/work/Test/live/…-тест.md`.

## 5. Як провести дзвінок

### 5.0 Перед дзвінком: модель і підготовка

**Яку модель обрати для сесії.** Кожна секунда роздумів моделі додається до затримки
підказки, тому вибір залежить від дзвінка:

| Дзвінок | Модель | Чому |
|---|---|---|
| Звичайні синки, стендапи, статуси | Sonnet 5.5, low або medium effort | Встигає за розмовою і досить уважна для перевірки відповідей |
| Інтерв'ю з клієнтом, ескалація, steering, важкі переговори | Opus 5.5 | Глибше бачить суперечності й недомовки; затримка 10-30 с на таких дзвінках прийнятна |
| Haiku | не рекомендовано | Занадто поверхово для перевірки відповідей і нюансів кількох мов |

**Підготовка в тій самій сесії.** Найкраще працює так: відкрити сесію в проєкті Cowork,
спершу зробити prep, а безпосередньо перед дзвінком написати `live tips`.

1. Prep: `client-meeting-prep` або `daily-team-prep`, чи вільний запит на кшталт
   "підготуй мене до інтерв'ю з клієнтом про звіти по транзакціях, візьми в першу чергу
   сторінки Notion <посилання> і папку <шлях>". Деталі мітингу, цілі, питання, сторінки й
   папки, які варто взяти в контекст першими, пишеш тут.
2. Перед дзвінком: `live tips <проєкт>`. Скіл бачить усе, що підготовлено раніше в сесії,
   і будує Live Brief довкола цього: цілі й питання з prep стають чеклістом, вказані
   сторінки й папка стають основою карти тем. Це пріоритет, а не обмеження: решта
   контексту проєкту (рішення, ризики, трекер, минулі мітинги) теж підтягується і
   використовується, коли розмова йде вбік.

**Вступне слово і "твоя черга".** Під час старту скіл заздалегідь готує "Мій апдейт":
3-4 пункти за пріоритетом (зроблено, в роботі, блокери чи потрібне рішення, далі) і готове
перше речення. Бере їх з prep-звіту на цей мітинг у Reports DB (той, що генерує скедулена
таска, наприклад `daily-team-prep`, або зроблений раніше в сесії) і з трекера. Для мітингу
по кількох проєктах, як-от внутрішній ПМ-синк, буде рядок на проєкт.

- **Починаєш ти** (ти ведеш мітинг, сказав про це, або перші 30 с з того боку тиша): одразу
  після чекліста приходить вступ: привітання, мета мітингу одним реченням, порядок тем або
  твій апдейт.
- **Тебе кличуть:** коли хтось звертається на будь-яке ім'я з `settings.user.name_aliases`
  (наприклад "Ваня", "Іване", "Ivan", включно з кривим написанням від Whisper) з
  проханням розповісти апдейти, приходить підказка 🔴 "Твоя черга", без жодних лімітів
  частоти. У ній перше речення і пункти в порядку, в якому їх казати. Якщо питали про одну
  тему, буде лише ця тема.

> **🔴 Твоя черга: апдейт**
> "Коротко по Acme: все за планом, одне питання."
> 1. Звіт по транзакціях на тестуванні
> 2. Оплати: чекаємо відповідь клієнта
> 3. Потрібне рішення: дата релізу

**Перемикання мови посеред дзвінка.** На внутрішніх дзвінках можлива і українська, і
англійська. Твій мікрофон розпізнається лише серед твоїх мов (`me_langs`,
наприклад українська й англійська), тому українська не перетвориться на російську, а
англійська вставка розпізнається правильно. Скіл тримає "мову моменту": якщо тебе просять
"розкажи це англійською" або гість питає англійською, одразу приходить підказка з суттю
українською і фразою вже англійською, і далі фрази йдуть англійською, поки ти не
повернешся до української. Російської свідомо немає в наборах мов: російська фраза
записується українською. Додай `ru` у `langs`, лише якщо дзвінок справді цього потребує.

> **🟠 Тепер англійською: статус релізу**
> "Short update in English. The release is on track for Friday."

**Типи зустрічей.** Задаються у вікні (рядок шестерні) або словами в запиті:

| Тип | Що дає |
|---|---|
| Internal standup | Синк команди, хто б його не вів. Коли питають тебе: твій апдейт одразу (зроблено, в роботі, далі, блокери) і підказка "твоя черга". Коли ведеш ти: кого про що спитати, уточнення на розмиті апдейти, власники й дати, хто ще не звітував |
| Client meeting | Формулювання для клієнта; сигнали про нові вимоги, обіцяні дати й оцінки, суперечності з рішеннями; підказки "можеш додати" |
| Working session | Одна тема (інцидент, рішення, контракт): твоя позиція і ключові пункти, далі що додати чи спитати |
| Job interview | Обери роль. **Observer**: інтерв'юють іншого, ти бачиш, що містить сильна відповідь, а потім рядок ✓ / ~ / ✗ про відповідь. **Candidate**: готове "розкажи про себе" з першої секунди і готові відповіді з фактів твого CV; компанія замінює проєкт, контекст береться з твоїх сторінок пошуку роботи в Notion. **Interviewer**: уточнювальні питання на слабкі відповіді і заплановані питання, які ще не прозвучали. Після дзвінка: повний аналіз (таблиця відповідей, сильні сторони, прогалини, сигнали, рекомендація, як працював суфлер) |

**Коли питаєш ти.** Будь-який дзвінок може перемикатися між "питаєш ти" і "питають тебе".
Скіл помічає відрізки, де питаєш ти, відстежує заплановані питання (поставлене, з
відповіддю, частково) і підказує, де відповідь розмита. У підсумку твої питання з
відповідями.

**Підготовка наперед і коли запускати.** Перед важливим дзвінком напиши будь-коли "підготуй
live tips до <дзвінок>". Скіл у субагенті читає всі джерела (мітинги, треди, теми, рішення,
ризики, звіти, трекер, документи проєкту, найновіші файли в теці проєкту, `live/lessons.md`)
і зберігає бриф і миттєві картки. На старті підготовка, молодша за 3 години, підхоплюється,
тож факти є з першої секунди. Без підготовки запускай за хвилину до дзвінка чи вже на ньому:
запис стартує одразу, бриф збирається за перші 1-3 хвилини, і свіжий можна попросити
будь-коли (🔄 або "онови контекст").

### 5.1 Під час дзвінка

1. За хвилину до дзвінка напиши в Cowork: **`live tips <проєкт>`** (або "лайв підказки",
   "я на дзвінку", "дзвінок почався"). Якщо проєкт не названий, скіл спитає. Мову і
   тривалість можна дописати: "live tips acme, внутрішній, українською, 30 хв".
2. Скіл перевіряє, що інструмент встановлений і що нічого вже не пишеться, кладе
   `control/start.json` і чекає `recording` (5-20 с на завантаження моделі). Вікно Terminal
   "Live transcriber" відкривається само: запускати його не треба. Запис живе саме в ньому,
   бо дозволи macOS на мікрофон і системний звук видані Terminal. Вікно можна згорнути
   (Cmd+M) або сховати за іншими, але не закривати. Якщо все ж закрити, запис акуратно
   зупиниться, а вже записаний транскрипт залишиться.
3. У чаті з'являється `Запис іде: <файл>. Мови: я en, дозволені en+es.`, а за хвилину
   чекліст мітингу з Live Brief (відкриті теми, рішення, ризики, обіцянки з минулих
   мітингів, тікети) і `Підкажу, коли буде що додати.`
4. Далі скіл говорить лише тоді, коли спрацьовує тригер. Прямого питання він не чекає:
   коли хтось завершив думку на робочу тему і від тебе очікують реакції, він підказує, що
   можна додати ("Можеш додати: ...", 1-2 готові фрази).

| Рівень | Коли |
|---|---|
| 🔴 одразу | Прохання, схоже на нову вимогу; ПМ називає дату чи оцінку; суперечність ухваленому рішенню; сигнал незадоволення; ПМ сказав факт, що суперечить трекеру чи рішенням |
| 🟠 не частіше ніж раз на `comment_rate_seconds` | Момент для коментаря: хтось завершив думку (ідея, знахідка, план, сумнів, підсумок), а ПМ ще не відреагував: 1-2 фрази, щоб додати факт, поставити корисне питання чи запропонувати наступний крок |
| 🟠 не частіше ніж раз на `rate_seconds` | ПМ відповів не на те питання або не на все; розмита відповідь там, де чекали дату чи власника; співрозмовники перейшли на іншу мову (коротка суть); згадана тема чи тікет з брифу; питання без відповіді ~2 хв; 2/3 часу і непокриті пункти; 5 хв до кінця і неотримані рішення |
| тихо | Action items, нові вимоги, зобов'язання: потрапляють у підсумок |

**Швидкий старт.** За замовчуванням (`start.mode: window`) у чаті питається лише те, що
визначає, куди піде запис: проєкт, якщо ти його не назвав, або компанія для твоєї власної
співбесіди. Решта стартує з налаштувань за замовчуванням, і ти виправляєш її в рядку шестерні
у вікні: мова і мікрофон перемикаються одразу без втрати транскрипту, тип зустрічі й роль
перебудовують підготовку. `start.mode: chat` лишає стартові питання в чаті.

**Оновлення контексту посеред дзвінка.** Для несподіваного дзвінка або коли розмова пішла в
тему, якої немає в брифі: тисни 🔄 або пиши "онови контекст" / "refresh context" / "глянь
треди по X". Субагент перечитує джерела разом з темами останніх 10 хвилин, бриф і картки
оновлюються, а скіл наздоганяє все сказане за цей час: 1-3 хвилини без нових фактів, нічого
не губиться.

**Цикл не має замовкати.** Підказки є, лише поки триває хід Claude. Скіл не завершує хід
текстовою відповіддю під час дзвінка, плагін-запобіжник (розділ 4) блокує це механічно, а
вікно фарбує рядок стану червоним ("Claude is not listening") після 75 с без опитування:
тоді напиши "continue" у чат Cowork.

### Вікно-суфлер

Щоб не дивитись у вікно Cowork під час дзвінка, підказки показує окреме маленьке вікно
поверх усіх інших. Його відкриває сам записувач на старті запису, вгорі по центру екрана,
під камерою.

- **Що в ньому:** найновіша підказка зверху великим шрифтом, попередні нижче, тьмяніші. Унизу
  рядок стану запису. Кнопки (підказка при
  наведенні): `🎙` вимкнути мікрофон, `💬` як часто приходять підказки для коментаря, `A-` / `A+`
  розмір шрифту, `◐` прозорість, `📌` завжди поверх інших вікон (вимкнути, якщо заважає).
- **`🎙` мьют.** Записувач слухає мікрофон Мака і не бачить, чи ти замьючений у Meet або Zoom:
  стан кнопки мьюту в програмі для дзвінків ззовні не прочитати, а помилкова здогадка тихо
  губила б твої слова, тому кнопка ручна навмисно. Навіщо вона: у кафе, з музикою чи людьми
  поруч ти замьючений у зустрічі, але мікрофон усе одно чує кімнату, і Whisper записав би це
  так, ніби це сказав ти. Що робить кнопка: стає червоною (`🔇`), записувач перестає
  розшифровувати мікрофон (співрозмовників і далі записує), у транскрипті з'являються рядки
  `--- мікрофон вимкнено HH:MM:SS ---` і `--- мікрофон увімкнено HH:MM:SS ---`, у статусі
  `mic=muted`, а скіл не вважає твою тишу проблемою і не робить перевірку відповідей за цей
  час. Тисни ще раз, коли розмьютишся. Кожен дзвінок починається з увімкненим мікрофоном.
- **`💬` підказки для коментаря і що означають секунди.** Тебе рідко питають напряму; частіше
  хтось завершив думку й чекає твоєї реакції. Для таких моментів скіл надсилає підказку
  "можеш додати" ("момент для коментаря"). Число на кнопці це **мінімальна пауза між двома
  такими підказками**, а не таймер і не затримка: `45s` означає "не частіше однієї підказки
  для коментаря на 45 секунд". Без ліміту вікно коментувало б кожну фразу, а з дуже великим
  пропускало б момент. Кнопка перемикає: 45 с (за замовчуванням, так само як
  `tips.comment_rate_seconds`), 20 с (жвава дискусія, підказок більше), вимкнено (`0`, лише
  прямі тригери) і 90 с (рідкі підказки). Вибір запам'ятовується на наступні дзвінки й одразу
  передається скілу. Термінові підказки (нова вимога, хибна дата, "твоя черга") цей ліміт
  ігнорують.
- **Шестерня (рядок налаштувань).** Тип зустрічі, твоя роль на співбесіді, мова, мікрофон;
  відкривається сам після швидкого старту. Мову і мікрофон записувач застосовує одразу (у
  транскрипті з'являється рядок `--- мова ---` / `--- мікрофон ---`), тип і роль ідуть
  скілу. Кожна зміна показує, чи її застосовано.
- **ⓘ** пояснює кожну кнопку і опцію прямо у вікні. **🔄** оновлює контекст (вище).
- **⚡ Миттєві картки.** Підготовка пише 15-40 карток (фрази-тригери всіма мовами дзвінка і
  готова підказка) у `<транскрипт>.cards.json`. Записувач сам звіряє кожен новий рядок і
  показує картку за 1-2 с, ще до того, як Claude подумає; Claude потім лише доповнює те,
  чого картка знати не могла.
- **Смуга Agenda** під кнопками: пункти дзвінка з ✓ / ○ і лічильником (на співбесіді
  питання, на стендапі, який ведеш ти, люди). Клік по назві згортає.
- **Кнопки-питання** над полем вводу: **Suggest reply** (готова відповідь чи коментар по
  поточній темі, коли питання от-от прозвучить або хочеш включитись), **Catch me up**
  (останні ~5 хвилин у 3-5 рядках), **Decided so far** (рішення й задачі з власниками і
  датами), **What to ask now** (1-2 питання по відкритих пунктах). Відповіді з транскрипту,
  без пошуків, за кілька секунд.
- **✓ / ✕ на кожній підказці.** Використав або не до місця. Картка з ✕ вимикається до кінця
  дзвінка, два ✕ на той самий тип підказок роблять їх рідшими, а підсумок їх рахує.
- **Затримка на виду.** На кожній підказці видно, через скільки після фрази вона з'явилась
  ("+18s", помаранчеве понад 20 с); у рядку стану медіана ("tips ~N s behind") і
  "transcript N s behind", коли розпізнавання відстає.
- **Лічильник розмови** в рядку стану: твоя частка часу і поточний монолог ("You 41% ·
  speaking 1:35", помаранчевий після 1:30).
- **Рядок стану** внизу під полем вводу: запис, кількість рядків, попередження; червоне
  "Claude is not listening (N s)", коли цикл завис.
- **Поле внизу:** пиши питання чи коментар і тисни Enter. Скіл отримає його в тому самому
  циклі, де читає транскрипт, і відповість у це ж вікно. "стоп" у полі зупиняє дзвінок так
  само, як у чаті.
- **Вікно звичайне:** його можна перетягнути, змінити розмір, згорнути (жовта кнопка або
  Cmd+M) і закрити (червона кнопка або Cmd+W). Закриття вікна запис не зупиняє. Позицію і
  розмір воно запам'ятовує.
- **Закрив випадково?** Напиши в чат "відкрий суфлер" або в Terminal
  `touch ~/work/Tools/live-transcriber/control/prompter`. За секунду вікно відкриється знову
  з усіма підказками від початку дзвінка.
- **Демонстрація екрана:** вікно просить macOS не потрапляти в запис екрана
  (`sharingType = none`). Чи слухається цього конкретна програма для дзвінків, залежить від
  того, як вона захоплює екран, тому перевір один раз сам (розділ 10). **Перевірено
  2026-10-11:** Google Meet у Chrome на macOS 26, демонстрація всього екрана, вікна в
  показаному зображенні немає. Для інших програм (Zoom, Teams) не перевірено. Якщо
  сумніваєшся: показуй не весь екран, а окреме вікно чи вкладку.
- **Куди йдуть підказки** задає `tips.output` у `settings.yaml`: `window`, `chat` або
  `both` (за замовчуванням). Чат лишається запасним варіантом.
- **Демо без дзвінка:** `python3 ~/work/Tools/live-transcriber/bin/demo_prompter.py`
  відкриває справжнє вікно зі сценарієм дзвінка (картки, підказки, agenda, рядок
  налаштувань, кнопки-питання, червоне попередження; близько 2 хвилин). `bin/prompter --demo`
  показує лише три статичні підказки.

Технічно: скіл дописує підказки рядками JSON у `<транскрипт>.tips.jsonl`, вікно їх
показує; питання з поля вікно пише в `<транскрипт>.inbox.jsonl`, а `read_delta.py`
повертає їх скілу як `@@ASK`.

### Як виглядає підказка

Розраховано на маленьке вікно Cowork вгорі по центру екрана, під камерою, щоб погляд не
бігав. Тому кожна підказка має 2-5 коротких рядків (до ~45 символів), без таблиць,
заголовків і посилань.

1. **Суть**, жирним: емодзі і що відбувається, українською, до 7 слів. Завжди першим
   рядком, щоб за секунду зрозуміти, про що мова.
2. **Фраза**, в лапках, мовою дзвінка. Це готова мова, яку можна прочитати вголос як є,
   а не тези. 1-2 речення. Англійською прості речення до 12 слів, побутова лексика, Present
   або Future Simple, активний стан, без ідіом і довгих підрядних.
3. **Факти** (лише для статусу і розмови співрозмовників між собою): до 3 рядків до 8 слів.
4. **Джерело** (лише для 🔴 суперечностей і неточностей): один короткий рядок курсивом.

**Без абревіатур:** "нова вимога", а не CR, "термін", а не ETA. Ключів тікетів теж немає,
замість них назва теми. Імена людей і назви продуктів лишаються як є.

Приклади на англійському дзвінку:

> **🔴 Нова вимога. Не погоджуй зараз.**
> "Good idea. I will write it down. We will check it and come back to you."

> **🔴 Неточно: реліз 15.10, не 10.10**
> "Sorry, a small correction. The release date is October 15."
> _рішення від 30.09_

> **🟠 Питали про термін, не про обсяг**
> "About the date: I will confirm it with the team by Friday."

> **🟠 Між собою іспанською**
> Сумніваються, чи встигнуть протестувати до релізу.

На внутрішньому українському дзвінку і суть, і фраза українською.

Підказка з 🔒 спирається на внутрішнє джерело: її не можна повторювати клієнту вголос.
Оцінок у годинах скіл ніколи не пропонує: "оцінку дає виконавець, зафіксуй і повернись".

**Питання під час дзвінка.** Пиши в чат будь-що ("що ми обіцяли по X?", "який статус
ACME-123?"). Скіл відповідає коротко з брифу і транскрипту, потім продовжує слухати з
того самого місця. Якщо цикл зупинився, напиши "продовжуй".

## 6. Як завершити мітинг

Три рівноцінні способи. У кожному з них транскрипт закривається рядком
`--- кінець запису HH:MM:SS ---`.

1. **У чаті (звичайний шлях):** напиши `стоп`, `все`, `кінець` або `кінець дзвінка`. Скіл
   створює `control/stop`, чекає до 60 с, поки дорозпізнаються останні фрази, і читає
   останні рядки.
2. **У вікні Terminal** "Live transcriber" (воно відкрилось само на старті): Ctrl+C або
   закрити вікно. Це запасний шлях, якщо чат недоступний. Скіл побачить `stopped` на
   наступному опитуванні.
3. **Автоматично:** якщо після щонайменше 20 рядків `idle_stop_minutes` хвилин немає нових
   реплік, скіл один раз питає "Дзвінок закінчився? Зупиняю запис через 2 хв" і зупиняє.
   Жорстка межа: запланована тривалість + 20 хв або `hard_cap_minutes`.

Важливо: **закриття Zoom/Meet запис не зупиняє.** Інструмент далі слухає системний звук
(музику, відео). Треба один із трьох способів вище.

Вручну без скіла: `touch ~/work/Tools/live-transcriber/control/stop`.

## 7. Що відбувається після дзвінка

### 7.1 Підсумок у чаті (українською)

Action items (хто / що / коли), нові вимоги, наші зобов'язання, відкриті питання,
"Відповіді, до яких варто повернутись" (питання → що не так → як закрити), непокриті пункти
чекліста, шлях до транскрипту, посилання на сторінку в Notion. Далі скіл лише пропонує
наступні кроки (звіт, change-request, risk-register) і нічого не запускає без команди.

### 7.2 Сторінка в Meetings DB (автоматично)

**Без дублікатів.** Той самий дзвінок ти часто паралельно записуєш Notion AI Meeting Notes.
Тому скіл спершу шукає сторінку цього мітингу: посилання, яке ти дав, інакше нотатки Notion
AI, що почались у межах 20 хвилин від запису, інакше сторінки Meetings DB того ж часу
(повторний пошук через ~60 с: Notion AI буває доробляє сторінку пізніше). Знайшов: дописує в
кінець один розділ "Live Tips: підсумок і роздуми", що б уже не було на сторінці, ніколи не
змінює наявні блоки, додає свій транскрипт, лише якщо на сторінці його немає, і заповнює
`Project`, `Workspace`, `Date`, лише якщо вони порожні. Кілька кандидатів: питає, який саме.
Жодного: створює одну сторінку в `notion.meetings_db` проєкту:

| Що | Значення |
|---|---|
| Назва | `<згенерована назва> @<дата-час початку>`. Назву скіл складає з того, про що реально говорили (2-6 слів, мовою дзвінка). Дата-час у назві є Notion date mention, тобто клікабельною датою, як у нативних AI Meeting Notes |
| `Date` | Дата і час початку мітингу (`started_at` зі `status.json`, з часовим зсувом Мака) |
| `Project` | Сторінка проєкту (`notion.project_page_id`) |
| `Workspace` | Воркспейс, до якого належить проєкт: береться з relation `Workspace` на сторінці проєкту (запасний варіант `notion.workspace_page_id`). Приклад: проєкт належить воркспейсу компанії, у якій ти працюєш |
| `Meeting type` | Лише якщо тип мітингу точно збігається з наявною опцією; нові опції скіл не створює |
| `Summary` | 1-2 речення |
| Тіло | Блок AI Meeting Notes з транскриптом, під ним розділ "Підсумок" (action items як to-do, нові вимоги, відкриті питання) |

**Обмеження Notion API (перевірено 2026-10-11).** Секції `Transcript` і `Summary` блоку AI
Meeting Notes через API не записуються: специфікація Notion прямо каже, що запис у
`<transcript>` завершується помилкою. Генерацію саммарі Notion AI через API теж не
запустити. Тому:

- транскрипт кладеться в секцію **Notes** блоку AI Meeting Notes (по рядку на абзац);
- саммарі пише сам скіл (поле `Summary` і розділ "Підсумок");
- якщо хочеш саммарі саме від Notion AI, натисни Notion AI у блоці вручну.

Технічна деталь, щоб не наступити вдруге. `notion-create-pages` зберігає
`<mention-date …/>` у назві як звичайний текст. Тому скіл спочатку створює сторінку з
простою назвою, а потім ставить назву з датою через `notion-update-page`
(`update_properties`), який mention розпізнає. Після цього скіл перечитує сторінку і
перевіряє назву, поля і кількість рядків.

Якщо мітинг записувався через Notion AI Meeting Notes (fallback, розділ 8), друга сторінка
не створюється: справжній транскрипт уже є в Notion.

---

### 7.3 Уроки з твоїх нотаток

Усе, що ти пишеш під час дзвінка не як питання ("тут правильніше було відповісти так",
"такі підказки не треба", "запізно"), збирається разом з оцінками ✓ / ✕ і проблемами циклу.
Після дзвінка скіл показує два пронумеровані списки: **уроки проєкту** (ідуть у
`<тека проєкту>/live/lessons.md`, який кожна наступна підготовка цього проєкту читає першим
і перетворює на правила брифу й картки) і **зміни скіла** (проблема, зміна, де). Без твого
"так" нічого не змінюється; схвалені зміни скіла приходять карткою на збереження (або
пакетом `.skill`) плюс рядок у `Skills/live-tips-changelog.md`.

## 8. Fallback: Notion AI Meeting Notes

Якщо Мак офлайн або live-transcriber не стартує, увімкни запис у Notion AI Meeting Notes
і скинь скілу посилання на сторінку мітингу. Скіл читатиме транскрипт звідти. Підказки
будуть менш точні: у Notion немає міток спікерів, а українську мову він подекуди
перетворює на кострубату англійську. Для цього режиму є окремий скіл `notion-live-tips`
(у пакет не входить).

## 9. Налаштування `settings.yaml`

| Ключ | Що задає |
|---|---|
| `user.me_label`, `user.them_label` | Мітки каналів у транскрипті |
| `user.tips_language` | Мова підказок і підсумку |
| `user.name_aliases` | Як тебе кличуть на дзвінках (усі форми і мови): тригер "Твоя черга" і підказка для Whisper |
| `user.timezone` | Запасна IANA-зона. Зазвичай не потрібна: live-transcriber сам пише в `status.json` зону і зсув годинника Мака (Notion приймає `Europe/Kiev`) |
| `start.mode` | `window` (за замовчуванням): запис стартує одразу з налаштуваннями за замовчуванням; тип зустрічі, роль, мова і мікрофон задаються в рядку шестерні у вікні. `chat`: спершу стартові питання в чаті |
| `start.ask` | Лише з `start.mode: chat`: `true` питає мову дзвінка і мікрофон; `false` бере значення за замовчуванням з цього файлу |
| `audio.mic` | Який мікрофон записувати: `default` = той, що зараз вхідний у Маку (AirPods, Jabra чи інші навушники, або сам Мак), `mac_mic` = завжди мікрофон самого Мака. Можна сказати й на старті: "live tips, мікрофон маку" |
| `workspaces` | Необов'язково: загальні дзвінки про кілька проєктів (назва, `project_root`, список slug проєктів); перші в питанні про проєкт |
| `project_roots` | Необов'язково: тека запису для slug проєкту, перекриває конфіг проєкту |
| `hiring.candidate` | Необов'язково, для твоїх власних співбесід: `root` (записи), `job_tracker` (джерело даних Notion з Company, Vacancy, Status, Stages log), `hub_page`, `recap_page`, `truth_bank_page` (факти твого CV, єдине джерело фактів про тебе) |
| `paths.work_root` | Папка Мака, підключена до Cowork |
| `paths.tool_root` | Де лежить live-transcriber |
| `languages.internal` | `me_lang` (основна мова мікрофона), `me_langs` (мови, на які ти можеш перейти, напр. `[uk, en]`), `langs` (усі мови дзвінка, перша основна, напр. `[uk, en]`) для внутрішніх дзвінків |
| `languages.client` | Те саме для клієнтських; `from_project` = `client_language` з конфігу |
| `languages.per_project.<slug>.<internal\|client>` | Перевизначення для конкретного проєкту |
| `tips.rate_seconds` | Мінімальний інтервал між некритичними підказками |
| `tips.answer_check` | Перевіряти відповіді самого ПМа |
| `tips.comment_prompts`, `tips.comment_rate_seconds` | Підказувати, що додати, коли інші завершили думку, без прямого питання; мінімальний проміжок між такими підказками |
| `tips.side_talk_summary` | Підсумовувати розмову співрозмовників між собою іншою мовою |
| `tips.output` | Куди йдуть підказки: `window` (вікно-суфлер), `chat` або `both` |
| `tips.idle_stop_minutes`, `tips.hard_cap_minutes` | Автостоп |
| `model_hint` | Яку модель Claude брати для сесії (див. розділ 5.0) |

**Де лежить `settings.yaml`.** Це файл усередині скіла `live-tips` у твоєму акаунті Claude,
а не окремий файл на Маку. Щоб його змінити, правиш файл у папці скіла і завантажуєш скіл
заново (zip з папкою `live-tips/`, де лежать `SKILL.md` і `settings.yaml`) у налаштуваннях
Claude, розділ Skills. У репозиторії шаблон лежить у `plugin/skills/live-tips/settings.yaml`.

Тонкі параметри розпізнавання (`vad_mode`, `end_silence`, `max_segment`, вікно відлуння,
`lang_bias`, `gap_resync`)
лежать у `DEFAULTS` в `src/transcriber.py` і за потреби перевизначаються в `config.json`.

## 10. Траблшутінг

| Симптом | Причина і що робити |
|---|---|
| Червоне "Claude is not listening" у вікні | Хід Claude завершився, і дзвінок ніхто не читає. Напиши "continue" у чат Cowork. Встанови плагін-запобіжник (розділ 4), щоб цього не траплялось |
| Не з'являються ⚡ картки | Картки беруться з підготовки: `<транскрипт>.cards.json` ще немає (бриф ще збирається або підготовки не було). Тисни 🔄 або готуйся наперед |
| Дві сторінки одного мітингу в Meetings DB | Стара версія скіла створила сторінку, не пошукавши сторінку Notion AI. Поточні шукають спершу; один раз злий дві вручну |
| Випадково закрив вікно-суфлер під час дзвінка | Напиши в чат "відкрий суфлер" або `touch ~/work/Tools/live-transcriber/control/prompter`. Воно відкриється за секунду з усіма підказками від початку; запис увесь час тривав |
| Вікно-суфлер не відкрилось | `bin/prompter` не зібраний: перезапусти `install.sh` і подивись блок `build prompter` у `logs/install.log`; помилки запуску в `logs/prompter.log`. Підказки тим часом ідуть у чат |
| Вікно видно учасникам під час демонстрації всього екрана | Програма для дзвінків захоплює екран способом, що ігнорує `sharingType = none`. Показуй окреме вікно чи вкладку замість усього екрана або згорни суфлер на час демонстрації |
| `start.json` лежить, а запис за 60 с не стартує | LaunchAgent не завантажений або інсталяцію не запускали. `launchctl list \| grep live-transcriber`; якщо порожньо, запусти `install.sh`. Скіл у такому разі перейменовує файл на `start.json.pending`, щоб запис не стартував несподівано пізніше |
| `system=silent`, у транскрипті лише "Я" | Немає дозволу на запис системного звуку. System Settings → Privacy & Security → Screen & System Audio Recording → System Audio Recording Only → Terminal. Перевірка: увімкни звук і запусти `bin/audiocap --source system --seconds 5 \| wc -c`, має бути більше нуля |
| Голос тонкий чи спотворений у навушниках (навушники перейшли в режим дзвінка) | Запиши мікрофон самого Мака: `audio.mic: mac_mic` або скажи "мікрофон маку" на старті. У Meet лишай навушники. У шумному місці мікрофон Мака чує й кімнату, тож користуйся мьютом `🎙` |
| `mic=silent` | Дозвіл на мікрофон для Terminal (Privacy & Security → Microphone) або вибрано не той вхідний пристрій |
| У `audiocap-mic.log` багато `mic restart: engine configuration change`, кілька на хвилину; рядки "Я" спотворені і їхній час відстає | Петля перезапусків, виправлено в 1.6.3: перезапусти `install.sh`, щоб перезібрати `audiocap`. Рядок `health` показує `restarts=N`; один перезапуск на зміну навушників це норма |
| `no IO from tap-only aggregate, retrying with output device as clock` | Норма: запасний режим тактування системного тапу |
| `queue` росте, підказки запізнюються | Мак перевантажений (відео, збірка). Транскрипція наздожене; скіл попереджає один раз |
| Українська розпізнається як інша мова, імена спотворені | Перевір `me_lang` і що основна мова перша в `langs`; скіл кладе імена в `prompt` одним коротким реченням |
| Рядки "Субтитры создавал ...", "Продолжение следует...", "Дякую за перегляд", перелік імен по колу | Артефакти Whisper: модель вивчила титри субтитрів з інтернет-відео і "згадує" їх на тиші, музиці чи порваному звуці, а імена з `prompt` повторює петлею. Цього немає у звуці, це не вірус. Відфільтровується `HALLUCINATION_PATTERNS` і перевіркою петель у `transcriber.py`; нові шаблони можна дописати туди |
| Однослівні рядки на кшталт "Дзвінок.", "Наступного року.", "Відповідь.", "м-м-м" і українські рядки з позначкою `(en)` | Перше це Whisper, що повторює перше слово `prompt` на шумі, решта його шумові фрази й вигуки. Вони відкидаються (`clean_text`: одне-два слова, усі з prompt, самостійні шумові фрази, чисті вигуки). Кириличний рядок з позначкою `(en)` це хибна мовна позначка моделі: тепер позначка йде за абеткою тексту. Порядок рядків може відрізнятися від реального до ~15 с: кожен рядок має час початку своєї фрази |
| Транскрипт читається, але українська слабка | Спробуй `"model": "mlx-community/whisper-large-v3-mlx"` у `config.json`: точніша, але на кожну фразу в 2-3 рази більше часу, тож рядки з'являються пізніше. Спершу порівняй обидві моделі на своєму звуці скриптом `bin/bench.py` (розділ "Порівняння моделей" у README інструмента) |
| Після перевстановлення з іншим `launchd_label` Terminal відкривається двічі | Працюють два LaunchAgent. Вивантаж старий: `launchctl bootout gui/$(id -u)/<старий label>` і видали його plist з `~/Library/LaunchAgents` |
| У назві сторінки Notion видно `<mention-date …>` текстом | Назву поставили через create, а не через update. Див. розділ 7.2 |

## 11. Приватність і етикет

- Аудіо не зберігається: розпізнані фрази одразу дописуються в `.md`, аудіобуфери живуть
  лише в пам'яті.
- Транскрипти лежать у папці проєкту (`<проєкт>/live/`). Не додавай їх у публічні
  репозиторії.
- Сторінка в Meetings DB внутрішня. Скіл ніколи нічого не надсилає клієнту.
- Попереджай учасників, що ведеш транскрипт, як і з будь-яким записувачем. Вимоги до
  згоди різняться залежно від країни і договору з клієнтом.

## 12. Чекліст для колеги

1. Мак на Apple Silicon, macOS 14.2+, Python 3.10+, Xcode CLT.
2. `tools/live-transcriber` → `~/work/Tools/live-transcriber`, `bash install.sh`, обидва
   дозволи для Terminal, у `install.log` обидва піки більші за нуль.

4. Папка `~/work` підключена в Cowork, конектор Notion увімкнений.
5. У конфігу проєкту є `Local Paths` і Notion ID з розділу 4, крок 7.
6. Пробний дзвінок: `live tips <проєкт>` → поговорити → `стоп` → перевірити підсумок і
   сторінку в Meetings DB.
